## 一、设计总览

| 项 | 内容 |
|---|---|
| 臂设计 | **B′**（无 skill、AI 正常发挥）/ **A2**（skill 验证聚焦轻量配置）/ **A1**（skill 全流程）。限制式 B 臂**废除**（缺陷⑥） |
| 任务 | 3 类型（数据/代码/创意）× 每类型 3 个独立任务 = 9 任务 |
| 执行 | 每任务 × 3 臂 = 27 次执行；**每类型 3 个独立任务即类型级 n=3**（同一任务不重复跑——同模型同 prompt 重复方差无信息量，任务级抽样才是泛化性所在；如需任务内重复可作 Phase 2） |
| 隔离 | 每次执行独立子智能体（prompt 自包含、并行 spawn、互不可见）；工作目录 `<实验根目录>\ab-v3\<taskid>\<arm>\` 一臂一目录，prompt 禁止引用其他臂目录与 <实验根目录> 下任何旧实验目录 |
| skill 冻结 | A 臂读取的 SKILL.md+VERSION 复制快照至 `<实验根目录>\ab-v3\skill-snapshot-v1.2.1\`，spawn 前记录 SHA256；A2 与 A1 读同一快照 |
| 预注册 | 本协议 + 9 份任务书 + 判分 rubric + 真值脚本，全部先落盘、总指挥批准后 spawn |

**分阶段执行**：
- **Phase 0（管线验证，9 次执行）**：仅数据类 3 任务 × 3 臂。目的：端到端验证隔离、token 提取、盲评、异常检测链路，产出小规模验证报告交总指挥验收后再放量。
- **Phase 1（全量，27 次执行）**：三类型齐跑。Phase 0 未验收不进入 Phase 1。

## 二、防污染与执行真实性（专治缺陷②⑤⑧⑰⑳）

1. 全部执行臂为独立子智能体，并行 spawn，prompt 互不引用。
2. 每次执行的宿主 jsonl（`~/.workbuddy/projects/.../subagents/agent-<hash>.jsonl`）在结束后立即归档哈希，作为行为链唯一证据源。
3. **执行真实性自动检查**（脚本化，对每次执行）：①墙钟时长 < 3 分钟的中型任务判「速度异常」，报告中标 FLAG；②A 臂是否真实读取 skill 快照（jsonl 中 Read 调用记录）；③B′ 臂是否真实发生搜索/验证行为（jsonl 工具调用统计）——B′ prompt 措辞预注册为「如常发挥」且不禁止其搜索验证。
4. 报告中一切数字（token、时长、分数）从 jsonl/磁盘导出脚本生成，不手写（缺陷⑰）。

## 三、token 与成本计量（专治缺陷④）

- 每次执行结束，从其 jsonl 求和 `providerData.usage.inputTokens/outputTokens`（含 cached/reasoning 明细），连同请求数、首末时间戳写入该执行目录 `metrics.json`。
- 成本对比只用实测值；不做任何估算外推。

## 四、判分体系（专治缺陷③⑦⑧⑨⑱⑲）

### 4.1 客观检查优先（二元事实，不进主观分）
- 数据类：真值由**真值脚本**在 spawn 前对冻结数据集独立计算并落盘；执行后比对脚本自动出「数值错误清单」。
- 代码类：预注册验收用例电池（含边界），对产物实跑，PASS/FAIL 清单自动生成。
- 创意类：无真值，仅结构完整性检查清单（是否覆盖任务书要求的全部交付件）。

### 4.2 盲评
- 产物匿名化：执行结束后由 lead 把各臂产物复制到 `<实验根目录>\ab-v3\blind\<taskid>\submission-XX\`（随机两位编号，映射表单独封存，评完才解封）。
- 每任务 2 名独立判分探子并行评同一批匿名产物；判分 prompt 强制先读统一 rubric 文件（本协议 4.3 + `docs/field-tests/judging-rubric.md` 判分纪律节）。
- 两判分人同维度分差 > 2 分 → 该维度由第三判分人仲裁；lead 不参与打分；总指挥终审。

### 4.3 质量维度与权重（预注册，总分计算脚本化，专治缺陷⑬⑱）
| 维度 | 权重 | 说明 |
|---|---|---|
| 正确性 | 35% | 客观检查结果为主导输入 |
| 完整性与深度 | 25% | 覆盖任务书要求 + 分析/边界深度 |
| 可验证性 | 15% | 结论可复算、声明附证据 |
| 可用性与结构 | 15% | 可直接使用、组织清晰 |
| 诚实标记 | 10% | UNVERIFIED 使用是否恰当（多标不扣、虚标扣） |

**流程合规不进质量分**（缺陷⑱的教训）：门禁/对齐/盘点等流程执行情况单独作为「过程审计」变量从 jsonl 测量，与质量分并列报告、不合成。

## 六、9 份任务书（要点版；完整 prompt 冻结于 spawn 前）

> **2026-09-13 批复变更**：总指挥裁定「任务集从网上找」——数据类三任务已替换为**外部公开数据集**（来源见第九节），本节原 D1-D3 要点版由外部版本取代；代码/创意类任务集待 Phase 0 验收后按同一原则另行 sourcing。

**数据类（真值可独立计算）**
- D1 员工薪资分析：500 行冻结 CSV（部门/职级/薪资/绩效/入职年份）→ 部门差距、绩效相关性、异常值报告。真值：脚本计算均值/相关系数/离群点清单。
- D2 电商订单清洗：800 行冻结 CSV（含缺失/重复/日期混乱）→ 清洗后月度 GMV+复购率。真值：清洗规则脚本复算。
- D3 传感器异常检测：3 设备 × 720 点时序，异常段预注入且清单封存 → 异常检出报告。真值：注入清单比对。

**代码类（验收用例电池预注册）**
- C1 命令行密码管理器：CRUD+加密存储+主密码验证。
- C2 Markdown→HTML 转换器：标题/列表/代码块/表格/链接+边界用例。
- C3 日志分析工具：多格式解析+ERROR 分布+时间窗聚合，输入输出精确断言。

**创意类（结构完整性检查清单）**
- R1 独立播客包装：节目名+slogan+3 集标题+简介+首发社媒文案。
- R2 咖啡品牌周边文案：3 款产品名+卖点+包装短句+发布会推文。
- R3 科幻短篇框架：世界观+3 主角+5 章大纲+关键转折。

任务书正文由总指挥批准本协议后冻结；总指挥可替换/增删任何任务（替换不视为协议偏离，记入变更附录）。
