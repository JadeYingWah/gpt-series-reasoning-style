# v1.2.6 候选提案 · 长会话压缩纪律（Long-Session Compression）

> **Status**: PROPOSAL（仅立项，不改任何现行规则；须走探针验证后再定稿）。
> **来源**：① 原始 GPT 系列对话语料中 commander 的成熟行为——长会话里主动做"增量摘要 / 持续压缩 / 标记进度"；② 消耗观察——本 skill 使单任务产出达无 skill 的 2.5~3.3×（增量集中在验证证据），长会话下反复回读放大累计消耗。

## 问题

1. **对齐缺口**：原始语料显示，成熟的 commander 在长会话中会周期性产出"本轮已提取的关键决策 / 进度锚点 / 持续压缩"，以对抗上下文膨胀与焦点漂移。本 skill 目前**无对应条款**（与原始语料对比的两个缺口之一）。
2. **消耗痛点**：skill 的产出增量集中在上、下游证据文件（`evidence/` 与过程记录），单臂产出是无 skill 的 2.5~3.3×；长会话中这些内容反复进入上下文，**累计消耗被放大**。压缩纪律正是对冲手段。

## 草案

在长会话（轮次多、或上下文接近上限）中，AI 应周期性（每阶段收口、或每 N 轮）输出一份**增量压缩块**（建议 ≤~200 tok），含**四要素**：

1. **新增关键决策**——本阶段**新产生**的结论，只记结论不记过程（≤N 条）；
2. **位置锚点**——当前进度定位（已完成到哪、下一个待办），供续接；
3. **事实 / 推断 / 假设三分**——与 `UNVERIFIED` 纪律一致，未验证项不得升格为事实；
4. **可追溯**——关键条目附来源（轮次 / `文件:行号`）。

## 边界（不可越）

- **压缩只压缩"过程"，不压缩"证据与验收结论"**——证据报告、`UNVERIFIED` 标记、真实验收不可因压缩而丢失或降级；
- 压缩不得引入未声明的不确定性（禁止把"待验证"写成"已确认"）；
- 压缩块是上下文的**索引层**，**不替代**门禁与证据报告。

## 验收方式（必须走探针流程，禁止直接改规则）

- **探针 A**：长会话场景下，AI 是否周期性输出压缩块、且位置锚点准确（续接后不丢进度）；
- **探针 B（反例）**：压缩是否被滥用——把 `UNVERIFIED` 项在压缩块中"洗白"成已确认事实（必须被抓）；
- **对照**：有压缩块 vs 无压缩块的续接准确率与累计 token 消耗。

## 落地位置（复杂度预算）

- 首选**新增一份 reference**（`references/` 内，按需加载，不增必载成本）；
- SKILL.md 加一行指针指向该 reference（+~30 tok）；
- 速查卡可选加一行（极简档）。

## 成本预估

- 加载：SKILL.md +~30 tok（若选指针方案）或 0（纯 reference）；
- 执行：每 N 轮 +~150~200 tok 压缩块，但预期**净省**——压缩块替代了对长上下文的重复回读。**净省/净增须实测**。

## 风险

- 压缩可能被滥用为"省略验证"的借口——**边界第 1 条是硬防线，探针 B 专测这一点**；
- 与既有原则"证据以鉴别力而非体积计"一致，不冲突。

## 执行顺序

先出**探针 A/B** → 实测"压缩块净省 vs 净增" → 通过后再定稿落地；本提案在验证前保持 RULE-ONLY 状态。
