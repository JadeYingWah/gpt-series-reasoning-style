# 冒险类任务 A/B 实验报告

## 实验设计
- 任务：设计文本冒险游戏完整关卡——"星际逃生"，包含剧情分支、选择系统、多个结局，并验证分支逻辑完整性
- 任务类型：纯冒险类（互动叙事）
- 三个臂：
  - **B 臂**：无 skill（基线，直接写关卡）
  - **A2 臂**：精简流程（1次互动叙事最佳实践搜索 + 结构化关卡 + 状态系统）
  - **A1 臂**：全流程（最佳实践搜索 + 分支逻辑自动化验证 + 结局可达性检查 + 2轮循环审查 + 时间平衡分析）

**A1臂通过自动化验证发现了真实缺陷**：初始设计中有2个结局不可达（独自逃生、窒息），因为逃生舱直接指向固定结局，没有根据玩家状态动态判定。修复方案是增加"结局判定"状态机场景，根据氧气和盟友数量动态判定结局。修复后所有4个结局均可达。

这证明：**冒险类任务中，人工审查容易遗漏不可达结局和死胡同，自动化分支逻辑验证是必要的**。

## 关键发现

### 1. 冒险类任务中，"写了分支≠分支正确"
- B臂和A2臂都有分支结构，但都没有验证分支逻辑的正确性
- 可能存在死胡同、不可达结局、无意义选择、状态不一致等问题
- A1臂通过自动化验证发现并修复了2个不可达结局
- **冒险类任务的交付物必须包含分支逻辑验证，不能只有文字描述**

### 2. 状态机结局优于固定指向
- A2臂的结局是固定指向（选择→结局），导致部分结局不可达
- A1臂使用状态机判定（最终状态→结局），所有结局均可达
- 这是互动叙事设计的最佳实践：结局应该是状态的函数，而非选择的直接结果

### 3. 自动化验证能发现人工审查遗漏的问题
- 不可达结局是隐蔽的缺陷——人工阅读很难发现"这个结局永远到不了"
- 验证脚本通过BFS遍历可以系统性地检查所有结局的可达性
- 无意义选择检测也能帮助设计师砍掉"假选择"

## 对模块化选择矩阵的调整建议

### 冒险类专属配置
1. **实操验证 = 逻辑验证（中等以上规模必选）**：
   - 分支完整性检查（所有选择都有目标）
   - 死胡同检测（无选择且非结局的场景）
   - 结局可达性检查（BFS遍历，所有结局必须可达）
   - 无意义选择检测（无效果且无条件的选择）
   - 状态一致性检查（物品获取/使用追踪）
   - 轻量任务可仅做结局可达性检查
2. **循环审查第1轮必须包含分支逻辑检查**：死胡同、不可达结局、状态一致性
3. **必须有自动化验证脚本**：可复现验证结果
4. **结局必须使用状态机判定**：根据最终状态动态判定，而非固定指向
5. **每个选择必须有不同后果**：无意义选择必须删除（验证脚本检测）
6. **网络搜索聚焦互动叙事最佳实践**：有意义选择、收敛点、延迟后果、状态追踪

### 与其他类型的区别
- 数据类：验证数据准确性（Python计算）
- 研究类：验证来源可靠性（多源交叉）
- 视觉类：验证技术规范（对比度+可渲染性+可访问性）
- 建模类：验证模型技术正确性（OBJ语法+UV+法线+PBR参数）
- 冒险类：验证分支逻辑正确性（完整性+可达性+一致性）
- 代码类：验证功能正确性（测试+边界）
- 创意类：验证结构完整性（创意结构化检查）

## 实验局限
- 单任务样本（n=1），结论需更多冒险任务验证
- 质量评分为主观评分，但分支验证结果是客观指标
- 验证脚本为简化版，未检查所有边界条件（如生命值≤0的结局）
- 未在真实游戏引擎中测试游玩体验
- 文本内容为设计文档，非可运行游戏
- 未测试多周目继承和隐藏结局
- token消耗为估算值，非精确计量
