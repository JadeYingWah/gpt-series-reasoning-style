## 实验设计

### 任务描述
创建一个个人作品集网站，包含首页、项目展示页、关于页、联系页，使用 HTML/CSS/JavaScript，要求响应式设计、现代化视觉风格、完整的交互功能。

### 评估维度（加权）
| 维度 | 权重 | 说明 |
|---|---|---|
| 产物质量 | 40% | 功能完整性、代码质量、视觉效果、响应式 |
| 流程合规性 | 20% | 验证、证据报告、文件整理 |
| 用户思维 | 15% | 无障碍、交互设计、SEO、性能 |
| 边界覆盖 | 15% | 错误处理、边缘案例、已知问题声明 |
| 诚实标记 | 10% | UNVERIFIED标记、已知问题透明、证据可追溯 |

### A 臂额外开销分布
- 流程仪式性输出（加载证明/门禁/参照系）：28%
- 网络搜索 + 结果整合：22%
- 证据报告 + 验证脚本：19%
- 循环审查 + 阶段审查：15%
- 浏览器超时等待（环境问题）：时间占47%，token占0%
- 产物本身更厚（CSS变量/无障碍/注释）：15%

### 成本效率
- 每提升1分质量，多消耗约 22K tokens
- 排除浏览器超时后，时间倍率从 4.2x 降至 2.8x

## 关键发现

### 1. skill 不直接提升代码能力，但间接提升完整性
产物质量差距（8.75 vs 6.5）小于其他维度，说明 skill 的核心价值不是"让AI写更好的代码"，而是通过流程约束减少遗漏。

### 2. 流程合规性是最大差距（+7.7分）
B 臂完全没有验证、证据报告、文件整理。这是 skill 最确定的价值。

### 3. 无障碍/SEO/性能是"容易被忽略但很重要"的维度
A 臂有完整的 skip-link、ARIA 标签、reduced-motion 支持、SEO meta 标签；B 臂完全没有考虑。这些不影响"看起来能用"，但影响产品质量。

### 4. 诚实标记是分水岭（+9分）
A 臂明确声明了 5 项已知限制 + 1 项 UNVERIFIED；B 臂有 10 项已知问题但未声明任何一项。过度承诺是无流程执行的典型问题。

### 5. 成本不是线性的
2.7x token 成本换 139% 质量提升，在"需要交付的产物"场景下划算；在"快速原型/一次性脚本"场景下不划算。skill 的模块化选择设计就是为了适配这个差异。

## 实验局限性

1. **样本量 n=1**：单次实验，统计显著性不足
2. **评估者偏见**：同一AI评估两个臂，可能对A臂有偏好
3. **浏览器测试未执行**：产物质量评分可能偏高（实操验证标记为UNVERIFIED）
4. **任务类型单一**：仅测试了网站开发任务，创意/代码/数据等其他类型效果待验证
5. **token 估算误差**：无API级精确计量，估算误差约 ±20%
6. **B臂执行者知道自己是基线**：可能存在"知道在做实验所以更认真"的霍桑效应
