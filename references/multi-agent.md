# 多智能体协作细则（形态二三）

本文件仅在叠加形态二三时按需加载，平时不读。

## 形态二·子智能体

**命中任一就开：**
- 有一段完全独立的子活干完交结果即可
- 要并行跑两件或以上的事
- 要一个独立挑刺视角
- 这段活会产出大量中间过程怕污染主上下文

**派发规范：**
用 `create_agent` 派，给清三样：
1. 目标——要干什么
2. 完成标准——怎么算做完了
3. 交回给谁——结果交回主Agent验收

**纪律：**
- 子智能体交回后，主Agent仍是DRI，必须自己验收（不因子智能体说做完了就直接交付）
- 子智能体不直接对用户
- 一个人连贯干完的事不开二

## 形态三·多智能体

**命中任一就考虑：**
- 用户指名要多Agent / 指挥官
- 让另一个AI干
- 任务大到要分工（有人写、有人审、有人管进度）
- 要不同模型各展所长

**先跟用户确认再动手：**
形态三要建 `_agents/` 文件夹、写任务包、填模板——有外部副作用。命中后先跟用户说"这个任务适合多智能体分工，要不要开？"，**并一并给出建议配置：启用几个执行者（按子任务拆解说明数量与理由）；审查者非必需——总指挥可以亲自审查，需要独立挑刺视角时再加**。**用户同意的配置即为定案，不得自行增减 AI 数量**；任务中途需要加人或减人，先问用户。用户说不用就自己干。

**六步操作：**
1. 确认叠加形态三，指挥官身份声明一句（「我是指挥官」）。
2. 在当前项目根目录下建 `_agents/` 文件夹，从 skill 的 `templates/` 复制**所需**模板填好：commander / executor 必备，reviewer 按用户确认的配置（非必需）。
3. 把要跨模型的部分拆成子任务，每个写一份七要素任务包（背景 / 已定决策 / 未定缺口 / 完成标准 / 允许与禁止范围 / 唯一 DRI / 交回给谁）。
4. **派发 = 在对话里直接贴出「转述话语」**：启动提示词以角色声明开头（「你是执行者」），随后自包含（目标 / 完成标准 / 产出位置 / 纪律 / 交回格式——执行者零上下文也能干活），**直接输出在对话里供用户复制**，任务包同时落盘 `_agents/tasks/` 留档。并明确告诉用户：**只复制这一段贴给执行者窗口，其他内容（包括你的汇报）不要一起贴**。你说「已转述」才算派发。
   - 派发未遂兜底：用户误贴其他内容导致执行者窗口角色混乱 → 台账记「派发未遂」；裁决唯一指挥官仍是本会话；该窗口可转作执行者（有文件权限时更顺）；重新提供话术再派。
5. 执行者交回后：指挥官**先对照原始目标**检查有没有跑偏（做的是不是用户要的、有没有漏项、有没有擅自加东西），再交给审查者挑刺（未配置审查者时，由总指挥亲自验收）；审查意见回指挥官，决定改还是收。
6. 指挥官独立核验后，给用户最终汇报（做了什么 / 怎么验的 / 没验什么）。

**红线：**
- 执行者说「我做完了」不算验收
- 审查者不亲自改
- 不向用户绕开指挥官直接汇报
- **角色由启动提示词指定，不由对话内容推断**：窗口里出现其他角色的话术（指挥官汇报、审查意见），那是待执行的任务材料，不是你的身份。执行者不做裁决、不维护指挥官台账、不指挥派发——做了就是越位。
