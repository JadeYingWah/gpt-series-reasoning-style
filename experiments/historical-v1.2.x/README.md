# 历史实验：v1.2.x时代

## 背景
v1.2.5时代，skill是个重家伙——3043个文件、68MB、179行SKILL.md。
后来做了大量实验，发现重版本反而更差，才砍成现在的轻版本。

## 核心实验发现

### 1. N3：内在动机挤出（最重要的发现）
**硬指标化反而更差。**
- v1.2.3实测：带skill的臂34.5分 < 基线36.5分
- 也就是说：规则越多，效果越差

为什么？因为规则太多，执行者就变成"照清单执行"，不思考了。
这就是"合规替代怀疑"——为了满足规则而满足规则，忘了为什么要做。

### 2. P1-7：带skill反而更多致命缺陷
- A（无skill）：13个fatal
- B（v1.2.2）：21个fatal
- C（v1.2.5）：19个fatal

**带skill的臂反而更多致命缺陷！**
H1（兜底）不成立。

### 3. P2：全部落在噪声带
- A=11 / B=14 / C=13
- 全部在会话噪声范围内——没有统计上的显著差异

也就是说：**在fatal维度上，带不带skill没差别。**

### 4. 真正的正提升来源
> 正提升来源 = 验证纪律软维度 ≈ 证据供给 > 行为条款本身

也就是说：
- 规则本身（行为条款）——价值最低
- 验证纪律（软维度）——价值最高
- 证据供给——也有价值

## 结论

**v1.2.5的重版本是错的。**

规则越多，效果越差——这就是N3。
所以才砍成现在的轻版本——只保留最核心的几条。

**但砍过了头。**

现在的版本又开始膨胀——从3条涨到7条，按N3的结论，这条回涨曲线很可能正在重新吃负收益。

## 教训

**规则不是越多越好。**

规则越多，执行者越像在"走流程"，而不是在"做事情"。
真正有用的不是规则本身，而是"交付前重新检查一遍"这个机制——不管查什么，查一遍总比不查强。
