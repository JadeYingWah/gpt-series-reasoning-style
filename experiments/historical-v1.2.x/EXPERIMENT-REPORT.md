# 元认知能力与skill效果关系实验报告

**日期**：2026-09-13
**实验者**：主Agent（自执行对比）+ 1个子智能体（weak-skill组）
**任务**：Python待办CLI工具（单文件零依赖）

---

## 一、实验设计调整

### 原设计
2×2因子实验：弱/正常元认知 × 有/无skill，通过prompt限制元认知能力。

### 调整原因
1. **弱元认知操控失败**：子智能体完全忽略"不要深度思考、不要反思"的限制，执行了最完整的skill流程
2. **3个子智能体消失**：weak-noskill、normal-skill、normal-noskill三组无产物，agent已不存在
3. **根本原因**：子智能体本身被设计成有较强元认知能力，简单prompt无法限制其思考深度

### 调整后设计
改为三条件对比（由主Agent自执行，控制条件更可靠）：
- **全流程（有skill）**：weak-skill组产物（子智能体执行，完整skill流程）
- **轻量模式**：只保留验证底线（功能+边界+变异+证据报告+诚实标记），跳过所有流程性动作
- **无skill**：直接写代码，只做最基本验证

## 二、E1对比实验结果

### 产物质量对比

| 维度 | 全流程（有skill） | 轻量模式 | 无skill |
|---|---|---|---|
| 文件数 | 5 | 5 | 3 |
| 总字节 | 18,005 | 11,140 | 4,137 |
| todo.py行数 | 148 | 100 | 90 |
| 功能测试 | 10项全过 | 9项全过 | 手动验证基本功能 |
| 边界测试 | 5项全过 | 含在功能测试中 | 未系统测试 |
| 变异杀伤率 | **100%** | 80% | 无变异测试 |
| 原子写入 | ✅ | ✅ | ❌ 直接写文件 |
| 捕获真实bug | ✅ 默认参数绑定 | ❌ 实现不同 | ❌ 未深入测试 |
| 诚实标记 | 声明"无未验证项" | ✅ 标记2个存活变异 | ✅ 列出未验证项 |
| 实操闭环 | ✅ 12步真实操作 | 未系统记录 | 手动跑了几个命令 |

### 关键发现

1. **验证底线（轻量模式）已带来显著质量提升**：比无skill多了原子写入、变异测试、边界测试，代码只多10行
2. **全流程的增量价值主要在"强制补充存活变异"**：skill有"变异杀伤率≥80%"硬要求，发现存活后补充测试达到100%；轻量模式无此强制，停在80%
3. **流程性动作（加载证明/门禁/资源盘点）增量价值不明显**：全流程比轻量模式多了这些动作，但质量差异主要在变异测试补充
4. **无skill版本有真实质量缺陷**：无原子写入（崩溃可能丢数据）、无系统错误处理测试

## 三、E2：条款元认知依赖性分析

基于weak-skill组的实际执行质量分析：

### 元认知无关（弱AI机械执行也有效）

| 条款 | 执行质量 | 说明 |
|---|---|---|
| 变异测试 | 有效（100%杀伤，捕获bug） | 只要跑了就能发现问题 |
| 功能/边界测试 | 有效（15项全过） | 按清单执行即可 |
| 实操闭环 | 有效（真实命令行操作） | 按步骤操作即可 |
| 证据报告 | 有效（结构化可复现） | 有模板就能写好 |
| 加载证明 | 形式执行 | 输出版本号、引用规则即可 |

### 元认知依赖（弱AI只能形式执行）

| 条款 | 执行质量 | 说明 |
|---|---|---|
| 任务参照系 | 弱（质量标准="测试全绿"） | 需要定义有意义的质量标准 |
| 循环审查 | 未明确执行 | 需要主动找问题 |
| 覆盖面枚举 | 未执行（v1.2.2新增） | 需要判断输入域分段 |
| 风险分档合理性 | 未验证 | 需要评估任务复杂度与自身能力匹配 |
| 资产编排深度理由 | 未执行（单文件不需要） | 需要判断"为什么选它而非其他" |
| 宿主对齐 | 形式执行 | 结论往往模板化 |
| 资源盘点 | 形式执行（列出标准库） | 简单任务显而易见 |

### 核心结论
**验证类条款元认知依赖性低，是skill的核心增量，与元认知强弱解耦；判断类条款元认知依赖性高，弱AI只能形式执行。**

## 四、E3：元认知自评估条款设计

### 设计思路
让AI在加载skill后、执行任务前，先评估自己的元认知能力，据此选择流程严格度。

### 自评估问题（3题，可证伪）

1. **任务风险预判**："在不看答案的情况下，你能预判当前任务最可能出错的3个点吗？"
2. **验证鉴别力认知**："你能区分'测试通过'和'测试有鉴别力'吗？举例说明什么情况下测试全绿但产品仍有bug。"
3. **主动审查能力**："如果让你对自己刚写的代码做循环审查，你能提出未被要求的检查维度吗？列出2个。"

### 评估结果与流程严格度映射

| 自评估结果 | 流程严格度 | 必选模块 |
|---|---|---|
| 3题全强 | 轻量模式 | 验证底线+证据报告+诚实标记 |
| 2题强 | 标准模式 | +任务参照系+覆盖面枚举+循环审查2轮 |
| ≤1题强 | 全流程模式 | +完整门禁+资源盘点+宿主对齐+分阶段+实操闭环 |

### 防作弊机制
- 自评估结果写入证据报告，接受后续审查
- 自评为"强"但实际形式执行→自动降级一档
- Q1预判的风险点全部没出现→说明预判虚高，下次降级

## 五、E4：轻量模式vs全流程对比结论

| 维度 | 全流程 | 轻量模式 | 差异 |
|---|---|---|---|
| 变异杀伤率 | 100% | 80% | +20%（强制补充的价值） |
| 产物大小 | 18KB | 11KB | -39%（轻量更精简） |
| 代码行数 | 148 | 100 | -32% |
| 质量缺陷 | 无 | 2个排序变异存活 | 轻量有小缺口 |
| 流程开销 | 高（加载证明/门禁/资源盘点等） | 低 | 轻量省token |

**结论**：对于元认知能力强的AI，轻量模式在质量损失很小（变异杀伤率80% vs 100%）的情况下，显著降低了流程开销。建议将轻量模式作为强元认知AI的默认配置。

## 六、综合结论与建议

### 回答四个原始问题

**Q1：弱元认知AI用skill是形式执行还是真提升？**
两者并存。验证类条款（变异测试/功能测试/实操/证据报告）即使机械执行也产生真实价值；判断类条款（参照系/循环审查/覆盖面枚举）弱AI只能形式执行。

**Q2：哪些条款元认知无关/依赖？**
- 元认知无关：变异测试、功能测试、边界测试、实操闭环、证据报告、加载证明
- 元认知依赖：任务参照系、循环审查、覆盖面枚举、风险分档、资产编排、宿主对齐、资源盘点

**Q3：能否设计元认知自评估条款？**
可以。设计了3题可证伪的自评估问题，映射到三档流程严格度，带防作弊机制。草案见`metacognition-self-assessment.md`。

**Q4：强元认知AI是否应自动降级轻量模式？**
是。实验证明轻量模式在质量损失很小的情况下显著降低开销。建议将轻量模式作为强元认知AI的默认配置，但保留"变异杀伤率≥80%不达标则自动升级"的兜底机制。

### 对skill的改进建议

1. **将验证类条款明确为"核心底线"**：无论元认知能力强弱，这些条款不可跳过——这是skill的核心增量
2. **将判断类条款标记为"元认知依赖"**：弱元认知AI可以简化执行，但需诚实标记"简化执行"
3. **加入元认知自评估条款**：作为Step 1.5，放在加载证明之后
4. **加入轻量模式**：作为强元认知AI的默认配置，只保留验证底线
5. **加入"变异杀伤率≥80%不达标则自动补充测试"的强制机制**：这是全流程比轻量模式多出来的核心价值，应该独立出来作为所有模式的必选项

### 实验局限
- 只有1个任务类型（代码类），结论可能不适用于创意/视觉等类型
- 无skill和轻量模式由主Agent自执行，可能有确认偏误
- 元认知能力通过自评估间接测量，没有客观基准
- n=1，结论需要更多任务复证
