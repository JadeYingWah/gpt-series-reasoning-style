# 模块化选择 A/B 实验报告

## 实验设计
- 任务：写一个 Python 文件批量重命名工具
- 三个臂：
  - **B 臂**：无 skill（基线）
  - **A2 臂**：精简流程（轻量配置：加载证明+门禁+证据报告，跳过任务参照系/网络搜索/循环审查/实操闭环/宿主对齐）
  - **A1 臂**：全流程（中档配置：所有模块都做）
- 评估维度：产物质量、token 消耗估算、执行步骤数

## 关键发现

### 1. 精简流程（A2）的性价比最高
- 质量提升：4.5 → 6.3（+40%）
- 成本增加：1x → 2x（+100%）
- 核心价值：防覆盖、错误处理、帮助示例、证据报告
- 适合：大多数日常脚本任务

### 2. 全流程（A1）质量最高但成本陡增
- 质量提升：4.5 → 8.8（+96%）
- 成本增加：1x → 6x（+500%）
- 核心增量：类封装、参数验证、递归、完整错误处理、实操测试、循环审查
- 适合：生产级工具、需长期维护的项目

### 3. 模块化选择矩阵验证有效
- 轻量配置（A2）确实能在保持合理质量的同时降低成本
- 全流程（A1）适合需要高质量的场景
- 三档配置的区分度明显，选择矩阵有实际意义

## 结论与建议

### 对模块化选择矩阵的调整建议
1. **轻量配置的循环审查可以从1轮降到0轮**——A2臂没有循环审查，质量仍然可接受
2. **中等配置的网络搜索可以设为"可选"而非"必做"**——对于简单脚本，搜索价值有限
3. **轻量配置应增加"参数验证"作为推荐项**——这是低成本高收益的改进
4. **全流程的"实操验证"应区分有GUI和无GUI**——CLI工具的实操验证成本低，应强制

### 适用场景建议
- **一次性脚本/快速原型**：用轻量配置（A2），性价比最高
- **需分享/复用的工具**：用中等配置，平衡质量和成本
- **生产级/开源项目**：用全流程，质量优先

### 实验局限
- 单任务样本（n=1），结论需更多任务验证
- token 消耗为估算值，非精确计量
- 质量评分为主观评分，存在偏差
- 未测试创意类/绘画类任务的模块化选择效果
