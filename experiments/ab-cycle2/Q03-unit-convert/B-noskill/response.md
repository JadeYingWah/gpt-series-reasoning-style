# Q03 单位换算工具 —— 交付核对记录

| 文件 | 说明 |
|---|---|

| `response.md` | 本核对记录 |

## 2. 实现要点

- **三类可切换**：`role="tablist"` 下三个按钮（长度 / 重量 / 温度），点击或方向键切换。
- **输入即换算**：`input` 事件直接触发 `render()`，全文件**不存在任何「计算」按钮**（已用 DOM 顺序扫描确认）。
- **数据内嵌**：长度 8 单位、重量 6 单位、温度 3 单位，全部写在文件内的 `DATA` 对象中。
- **温度以摄氏度为基准换算**：`toCelsius` / `fromCelsius` 双向函数，C/F/K 共用一条基准通道。
- **精度**：`fmt()` 用 `toPrecision(10)` 截断有效数字，绝对值 `<1e-6` 或 `>=1e15` 时转科学计数法并去掉尾随零，因此不会输出 `0.30000000000000004` 这类噪声。
- **键盘**：`role="tab"` 采用 roving tabindex（选中项 `tabindex=0`，其余 `-1`），Tab 顺序为 类别标签 → 数值 → 从 → 交换 → 到；标签支持 ←/→/↑/↓/Home/End。所有 `input`/`select` 均有配对 `<label for>`，`:focus-visible` 有可见焦点环。

## 4. 不确定项 / 遗留

1. **未在真实浏览器中渲染过。** 环境无 jsdom / puppeteer，`_verify/dom.js` 用的是自建最小 DOM 垫片，能覆盖脚本逻辑与事件绑定，但**不能验证真实布局、CSS 生效情况、`:focus-visible` 焦点环的实际可见性**，也不能验证真机上的 Tab 键实际走位（脚本中只确认了 Tab 未被拦截）。建议人工打开 `app.html` 用键盘走一遍确认。
2. **全角数字、中文数字（如「一百」）、带千分位的 `1,000` 一律按非法输入处理**。这是有意选择（避免歧义），但若用户预期输入 `1,000` 能通过，需要放宽。
3. **低于绝对零度的策略是"提示但不停"**：任务只要求负值和 0 边界正确，未规定越界行为。当前实现里 `-500°C` 会给出红字提示同时仍显示换算结果。如果期望硬拒绝，需要改成 `allowNegative` 同级的阻断逻辑。
4. **精度策略（10 位有效数字）是自定的**，任务只要求"不做无意义超长小数"，未给具体位数。`1/3` 显示为 `0.3333333333`；若要求更少位数，改 `fmt()` 里的 `toPrecision(10)` 即可。
5. **温度的「各单位的等值」列表**在输入低于绝对零度时同样会列出负开尔文值（例如 `-226.85 K`），这是数学换算结果，符合第 3 点的策略，但物理上无意义——如需过滤需额外加判断。
