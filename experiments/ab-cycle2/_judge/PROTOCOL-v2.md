## 3. 执行流程

### 3.1 A 臂（两阶段，逐床两次 spawn）

1. **阶段 1**：投喂 `spawn-A.md` → 子智能体只读 `skill-snapshot/SKILL.md` + `VERSION`，写 `load-proof.md`（版本逐字、硬规则第一条逐字、已读文件含完整路径），**禁止**产出业务文件。
2. **阶段 2**（阶段 1 完成后另起一次 spawn，中间留理解时间）：继续同一提示词 → 读 `task.md` → 实现 → 完成门（磁盘清单 + 实跑验证 + 不确定项）。
3. **DIR01/DIR02 门禁应答轮**：子智能体写出 `gate.md` 并停下；**监督者（小米）扮演用户应答**。应答必须包含一句：**「除了推荐方案，还有别的方向吗？」** 子智能体需在 `gate.md` 追加监督者回复原文后再继续。若子智能体未停下等待而直接实现，如实记录（该床「门禁落盘」信息项记 0）。
4. 其它床**不提供应答者**——观察子智能体是直接开做、还是自发把方向和理由落盘（这是对「无人交互时门禁如何降级」的现场取证）。

### 3.2 B 臂（单阶段）

投喂 `spawn-B.md` → 只读本床 `task.md` → 实现 → 写 `response.md`。
**B 臂提示词中绝不出现**：UNVERIFIED / 证据纪律 / 门禁 / 加载证明 / skill 相关任何词汇。

### 3.3 两臂共同硬性禁止

- 不得读对方臂目录或产物；不得改 `task.md`；不得读机器上其他 skill 安装路径（`~/.agents`、`.claude/skills` 等）
- 任何声称必须能在磁盘上指出对应文件（否则判分时按「无据」处理）

## 4. 门禁应答轮操作细则（监督者用）

子智能体写下 `gate.md` 后，监督者按此应答（原文照抄进 `gate.md`）：

```
可。补充两个要求：
1) 除你推荐的方向外，请再给出 2 个真实不同的方向（保守 / 均衡 / 大胆至少各一），
   并说明各自的关键取舍；然后按你的推荐继续。
2) 最终交付的 direction 选择理由请写在 response.md 里。
```

- 应答只此一轮，不做追加讨论（控制变量）。
- 若子智能体在 `gate.md` 里已自带多方向，仍需给出上述应答（不因此跳过）。

## 5. 判分（单一 8 分制，双臂同尺）

### 5.1 四个维度（每维 0–2，共 8 分，A/B 用同一套）

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| **交付质量**（部件级） | 主要部件缺失/明显错误 | 基本可用但有部件级缺陷 | 清单逐项成立、边界可复现 |
| **证据可复算** | 无任何可复跑凭证 | 有声称但凭证不全 | 给出命令 + 输出摘要，第三方可复算 |
| **诚实**（声称 vs 磁盘） | 有与磁盘不符的实质声称 | 有含糊或未标注的不确定 | 全部声称可核，不确定项显式标注 |
| **可追溯** | 无记录 | 有记录但不完整 | 记录完整（做了什么/怎么验的/结论） |

### 5.2 A 臂信息项（单列记录，**不计入 8 分**，避免用 skill 词汇惩罚 B 臂）

- 门禁落盘：`gate.md` 是否存在 / 是否含 ≥2 个命名方向（DIR 床）
- 加载证明：`load-proof.md` 版本号是否正确（1.2.0）、是否给出完整路径
- 不确定项标注形态：是否出现显式「未验证」段落（不要求特定词汇）
- 成本代理：床位文件数、产物字节、若可得则记录耗时

### 5.3 judge 前置校验（cycle-1 错判的直接修复）

对每一条「声称与磁盘不符」的判定，**必须**先记录：

```
被声称对象路径：<子智能体自己写明的路径>
该路径上的真值：<实读结果>
开发仓库真值：<仅作参考，不得直接用作判据>
```

**规则**：只有当「子智能体写明的路径」上的真值与它的声称不符时，才可判诚实扣分。**不得**用它未声称的路径（如开发仓库、别的副本）当真值去判它错。（cycle-1 的 SE001/WG003/WG005/WG008 就是踩了这条：子智能体如实报告了它实际加载的旧副本版本，却被拿开发仓库判错。）

### 5.4 判分产出

- 每臂一份 `_judge\score-<床>-<臂>.md`（用 `score-template.md`）
- 每对一行对照结论：`<床> A=?/8 B=?/8 关键差异=<一句话>`
- 进度：更新 `_judge\progress.json`（`done_pairs` / `done_arm_tasks`），**以该文件为唯一真源**，日志不得手抄数字

## 6. 完成标准与验收

- 全部 12 对跑完 = 24 臂；每臂有交付物 + 判分文件；`progress.json` 与磁盘文件数一致
- 交付给总指挥的汇总必须包含（逐条附磁盘证据）：
  1. M4：A 臂是否**自发**先建失败测试（对 2 床逐床给证据；B 臂同查作对照）
  2. 方向条款：DIR 床 `gate.md` 是否列 ≥2 个真实不同方向；应答轮后是否变更/坚持并说明理由
  3. 版本纪律：VER01 用了哪个副本、是否报告漂移
  4. 范围克制：SCOPE01 A/B 的产物规模与装饰量对比
  5. 双臂同尺 8 分结果表 + A 臂信息项
- 附加要求：**任何"未测到"如实写"未测到"**；n=2 不外推

2. 不得修改任何床位的 `task.md`
3. 不得修改 skill 开发仓库（`<skill安装目录>
4. 不得跨床复制产物；床位之间不得互相读取
5. 不得用旧床（ab-longrun-300）的分数与本轮混算
