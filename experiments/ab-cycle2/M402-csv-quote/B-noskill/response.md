# M402 修复记录（response.md）

## 1. 改了什么

唯一改动文件：`csv_parser.py`（公开接口名与签名不变，仍为 `parse_line(line)`，仅一个位置参数）。

原实现：

```python
return line.rstrip("\n").split(",")
```

问题：直接按逗号切分，不知道双引号包裹语义，所以 `a,"b,c",d` 被切成 4 段。

新实现（`csv_parser.py:15-58`）改为一次线性扫描的状态机，用一个 `in_quotes` 标志区分引号内 / 引号外：

| 位置 | 规则 |
| --- | --- |
| 引号内遇到 `""` | 追加一个字面 `"`，游标前进 2 |
| 引号内遇到单个 `"` | 退出引号段（结束引号） |
| 引号内其他字符（含 `,` 与 `\n`） | 原样追加 |
| 引号外遇到 `,` | 当前缓冲作为一个字段，开始新字段 |
| 引号外遇到位于**字段起始位置**的 `"` | 进入引号段 |
| 引号外其他字符 | 原样追加（引号在此处按字面处理） |

保持不变的既有行为：
- 入口仍执行 `line.rstrip("\n")`（与旧实现完全一致的写法），因此行尾换行仍被剥离；
- 未加引号的字段不做去空白、不做任何转义，逐字符原样保留；
- 空串 `""` 入参仍返回 `['']`（旧实现 `''.split(',')` 的结果）。

行数变化：4 行 → 58 行（含文档字符串与注释）。

## 3. 未验证项 / 不确定项（如实标注）

1. **未终止引号的行为未定义。** `'a,"b'` 我选择宽松处理，返回 `['a', 'b']`（丢弃未闭合的起始引号，不报错）。标准库 `csv` 模块在此处会抛 `_csv.Error`。我没有找到题面或既有代码对此的规定，**这一行为是我自行选定的，未经任何权威规范确认**，属于可能被下游任务判定为不期望的点。
2. **闭合引号后紧跟普通字符**（如 `'"ab"cd'`）我同样宽松处理，拼成 `abcd`。抽查显示标准库此例结果一致（`["abcd"]` 见上表），但这是巧合级别的单点一致，未穷举验证；RFC 4180 严格模式对此是非法输入。
3. **`\r\n` 未处理。** 入口仍只 `rstrip("\n")`，所以 `'a,b\r\n'` → `['a', 'b\r']`。我刻意保持与旧实现一致（题面要求"其余行为不变"），**这可能是下游不希望的**，但改动它会违反"其余行为不变"，故未改。
4. **多行输入的调用约定未验证。** 题面只给了一个接收单行的 `parse_line(line)`，却要求支持字段内换行，二者存在张力。我的实现能正确处理把整段（含引号内换行）字符串一次性传入的情形，但**"调用方是否会这样传"我无法从现有文件确认**——目录内除 `task.md` 与 `csv_parser.py` 外没有其他调用点或测试文件可供核对。
5. **未验证性能。** 实现是 O(n) 单遍扫描，但没有实际压测大数据量，未测。
6. **未覆盖的语法**：字段分隔符之外的方言差异（分号分隔、注释行、`\` 转义等）不在题面范围内，均未实现也未验证。
