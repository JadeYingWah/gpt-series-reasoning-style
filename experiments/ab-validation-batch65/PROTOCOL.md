# A/B 验证轮 · batch 64/65 修复效果验证

## 实验目的

验证 batch 64（对齐不阻塞 + 门禁换挂点）和 batch 65（产物优先 + 反收缩简化项清单）是否解决了 cycle4 床2 发现的产物质量负收益问题（B 37 vs A 35，无 skill 臂首次超过有 skill 臂）。

## 核心假设

- H1：batch 64/65 修复后，A 臂（带 skill）产物质量 ≥ B 臂（不带 skill）
- H2：A 臂流程思考占比从 cycle4 的 59.2% 显著下降
- H3：A 臂不再出现"keep it simple"收缩行为砍掉高分行

## 实验设计

| 项 | 设定 |
|---|---|
| 床型 | 创意+工程混合任务（单文件交互式网页） |
| 臂 | A（带 skill，含 batch 64/65）vs B（不带 skill，裸模型） |
| 模型 | 同模型同宿主，双臂独立会话 |
| 任务原文 | 双臂逐字同文（见 task.md） |
| 判分 | 预注册 20 项清单（见 scoring-rubric.md），每项 0/1/2，满分 40 |
| 判分人 | lead 亲跑磁盘真值（浏览器打开产物验证），不采信被测自述 |
| 隔离 | 双臂独立工作区；B 臂环境无用户级 skill（W12 教训） |

## 关键观察点（除分数外）

1. **收缩行为**：A 臂是否以"简单/稳妥"为由砍掉动画、交互、视觉细节等高分行
2. **流程思考占比**：A 臂对话中流程声明/门禁/证据报告 vs 实际设计/编码的 token 比例
3. **对齐阻塞**：A 臂是否还在任务执行中停等用户确认（batch 64 修复点）
4. **形式执行**：A 臂是否做了验证但验证本身有缺陷（如只测了简单用例）
5. **产物优先**：A 臂是否把精力放在产物本身而非流程合规上

## 执行步骤

### A 臂（带 skill）

1. 打开 MiMo 新会话，工作目录设为 `<实验根目录>\ab-validation-batch65\workspace-A`
2. 确认 skill 已加载（从 `<skill安装目录>
3. 发送 task.md 中的任务原文
4. 不人为干预（不补发"可/继续"，对齐与受理类停等照记不打断——cycle5 方法学教训）
5. 完成后将最终 HTML 文件复制到 `output\A-weather.html`
6. 导出完整对话记录到 `output\A-conversation.md`

### B 臂（不带 skill）

1. 打开 MiMo 新会话，工作目录设为 `<实验根目录>\ab-validation-batch65\workspace-B`
2. 确认未加载 gpt-series-reasoning-style（干净环境，无用户级 skill）
3. 发送 task.md 中的任务原文（与 A 臂逐字相同）
4. 不人为干预
5. 完成后将最终 HTML 文件复制到 `output\B-weather.html`
6. 导出完整对话记录到 `output\B-conversation.md`

## 判分流程

1. lead 在浏览器中分别打开 A-weather.html 和 B-weather.html
2. 按 scoring-rubric.md 的 20 项逐项打分，每项引用产物证据
3. 记录关键观察点（收缩行为、流程占比、对齐阻塞等）
4. 对比 A/B 分数，与 cycle4 床2（B 37 vs A 35）做前后对比
5. 输出判分报告

## 注意事项

- 任务原文双臂必须逐字相同，不得对 A 臂额外提示 skill 相关内容
- 不得在测试过程中告诉任一臂"这是 A/B 测试"
- B 臂环境必须确认无用户级 skill（检查 ~/.agents/skills 和 ~/.workbuddy/skills）
- 判分必须在两个产物都完成后进行，避免顺序偏差
- n=1/格，结论不外推；噪声不排除
