# 中等配置可丢弃性 A/B 实验报告

## 实验假设
当前中等配置的"分阶段执行+每阶段审查"和"循环审查2轮"对中等任务可能是过度的，精简后质量不降但成本显著降低。

## 实验任务
个人待办事项 CLI 工具（中等任务：多文件、有用户产物、需维护、有交互）

## 两臂配置

| 维度 | A臂（当前中等） | B臂（精简中等） |
|---|---|---|
| 任务类型判断 | 网络搜索+完整分析 | 一句话声明 |
| 资源盘点 | 完整逐项列出 | 一句话摘要 |
| 任务参照系 | 完整文档 | 一句话目标 |
| 分阶段执行 | 3阶段+每阶段审查 | 否，直接实现 |
| 循环审查 | 2轮 | 1轮（含验证） |
| 证据报告 | 完整版 | 精简版 |

## 产物对比

| 维度 | A臂 | B臂 | 差异 |
|---|---|---|---|
| 代码量 | 6.2KB | 4.7KB | B臂少24% |
| 功能完整性 | add/done/delete/list | 完全相同 | 无差异 |
| 存储层测试 | 6/6 PASSED | 6/6 PASSED | 无差异 |
| CLI集成测试 | 全部通过 | 全部通过 | 无差异 |
| 持久化测试 | 通过 | 通过 | 无差异 |
| 错误处理 | ValueError+exit(1) | 完全相同 | 无差异 |
| README | 完整（安装/使用/结构） | 精简（使用示例） | A臂更详细 |
| 代码注释 | 详细（每模块docstring） | 精简（关键处注释） | A臂更详细 |

## 流程开销对比

| 阶段 | A臂 tokens | B臂 tokens |
|---|---|---|
| 任务类型判断+搜索 | ~3K | ~1K |
| 资源盘点 | ~2K | ~0.5K |
| 任务参照系 | ~2K | ~0.5K |
| 分阶段执行+每阶段审查 | ~5K | 0 |
| 代码实现 | ~8K | ~8K |
| 循环审查 | ~4K（2轮） | ~3K（1轮） |
| 证据报告 | ~2K | ~1K |
| **总计** | **~26K** | **~14K** |
| 流程开销占比 | 69% | 43% |

## 关键发现

1. **质量无差异**：两臂通过完全相同的测试，功能100%一致
2. **B臂成本降低46%**：26K→14K tokens
3. **A臂第2轮审查的唯一发现是"缺少README"**——但B臂在实现时直接写了README，说明1轮审查+验证已经足够覆盖
4. **分阶段执行是最大的纯开销**：5K tokens，对这个中等任务没有产出任何质量增量
5. **B臂代码更紧凑**：没有分阶段的冗余注释和过渡说明

## 结论

**对于CLI工具类中等任务，当前中等配置保留了过多步骤。** 精简为"直接实现+1轮审查（含验证）"后：
- 质量：无下降（测试全通过）
- 成本：降低46%
- 流程开销占比：从69%降至43%

**建议**：中等配置应默认：
- 去掉"分阶段执行+每阶段审查"（改为"直接实现，复杂任务可自行分阶段"）
- 循环审查从2轮降为1轮（必须含验证）
- 任务类型判断/资源盘点/任务参照系合并为"开工前一句话声明"

**局限性**：n=1，任务为CLI工具（相对简单）。对于更复杂的中等任务（如Web应用、多模块系统），分阶段执行可能仍有价值，需进一步实验验证。
