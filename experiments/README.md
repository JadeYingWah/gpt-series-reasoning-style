# gpt-series-reasoning-style 实验记录

本目录收录了该 skill 从 v0.1 到 v1.6.0 所有 A/B 双臂对照实验的素材、结果和结论。

## 实验目的

验证这个 skill 到底有没有用、有什么用、什么时候用最好。

## 实验方法

所有实验都是**双臂对照**：
- A臂：带 skill（加载 gpt-series-reasoning-style）
- B臂：裸模型（不加载任何 skill）
- 两臂在空目录里从零开始，互不可见
- 任务完全相同，只有"有没有 skill"这一个变量

这样才能干净地归因——哪些差异是 skill 带来的，哪些是模型本来就会的。

## 实验阶段总览

| 阶段 | 版本 | 任务数 | 核心发现 |
|---|---|---|---|
| Test-Bed 1 | v1.4.18 | 6个轻任务 | skill不提升代码质量，提升的是交付可信度 |

## 核心结论

### 1. skill不提升代码质量，提升交付可信度

所有实验一致发现：
- 代码本体（架构、算法、功能覆盖）——两臂差别不大
- 交付可信度（有没有真验证、有没有列未验证项）——带skill的臂明显更好

也就是说：**skill不教你写代码，它教你别撒谎。**

### 2. 最有用的规则

从所有实验看，最有用的规则是：
1. **真打开看一眼**——防假完成，抓到视觉问题、端口劫持、假完成
2. **未验证标注**——诚实，不装成全验过
3. **全绿不算证据**——测试全过不代表没问题，故意做一次错误才算验过

### 3. 最没用的规则

从实验看，没什么用的规则是：
- 太细的流程——比如"几大步、几小步"，执行者根本记不住
- 太复杂的模板——比如23字段任务包，实际用的时候根本填不满

### 4. 最重要的设计：执行面彻底忘记skill

这个设计很聪明：
- 执行的时候不打断创作流
- 做完了再回来检查

两面分离——创作是创作，检查是检查，互不干扰。

### 5. v1.5.x关键迭代：减少创作摩擦

从v1.5.7开始的改动：
- **与其他skill共存**：只在阶段2/5介入，阶段1/3/4完全开放
- **B档硬上限**：未主动说"一个一个问"时最多1题专名确认
- **竖切优先**：A档确认后立刻做最小可玩切片
- **创作类跳过阶段2**：遇到陌生专名先搜再问，其他直接进阶段3

## 方法论说明

**为什么用双臂对照？**
因为单臂实验没法归因——你不知道是skill带来的差异，还是模型本来就会。双臂对照把"有没有skill"作为唯一变量，才能干净地看出skill的效果。

**为什么用空目录？**
因为要排除"之前做过类似的"这种干扰。两臂都从零开始，才能保证起点一致。

**n=1怎么办？**
单个实验的结论不做外推。所有结论都是多组实验一致后才写进这里的。
