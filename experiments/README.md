# gpt-series-reasoning-style 实验记录

本目录收录了该 skill 从 v0.1 到 v1.4.x 所有 A/B 双臂对照实验的素材、结果和结论。

## 实验阶段总览

| 阶段 | 版本 | 任务数 | 核心发现 |
|---|---|---|---|
| Test-Bed 1 | v1.4.18 | 6个轻任务 | skill不提升代码质量，提升的是交付可信度 |
| Test-Bed 2 | v1.4.18→v1.4.41 | 5个中等任务 | 最有用的规则是"真打开看一眼"和"全绿不算证据" |
| Test-Bed 3 | v1.4.41 | 1个创意任务 | 真打开看一眼能抓到视觉问题，结构校验抓不到 |
| Test-Bed 4 | v1.4.49 | 1个复杂创意任务 | 这套纪律学会了就忘不掉，知道了就会自觉用 |

## 核心结论

### 1. skill不提升代码质量，提升交付可信度

所有实验一致发现：
- 代码本体（架构、算法、功能覆盖）——两臂差别不大
- 交付可信度（有没有真验证、有没有列未验证项）——带skill的臂明显更好

也就是说：**skill不教你写代码，它教你别撒谎。**

### 2. 最有用的规则

从所有实验看，最有用的规则是：
1. **真打开看一眼**——防假完成，抓到视觉问题、端口劫持、假完成
2. **未验证标注**——诚实，不装成全验过
3. **全绿不算证据**——测试全过不代表没问题，故意做一次错误才算验过

### 3. 最没用的规则

从实验看，没什么用的规则是：
- 太细的流程——比如"几大步、几小步"，执行者根本记不住
- 太复杂的模板——比如23字段任务包，实际用的时候根本填不满

### 4. 最重要的设计：执行面彻底忘记skill

这个设计很聪明：
- 执行的时候不打断创作流
- 做完了再回来检查

两面分离——创作是创作，检查是检查，互不干扰。

## 方法论说明

所有实验都是**双臂对照**：
- A臂：带skill
- B臂：裸模型，不加载任何skill
- 两臂在空目录里从零开始，互不可见

这样才能干净地归因——哪些差异是skill带来的，哪些是模型本来就会的。
