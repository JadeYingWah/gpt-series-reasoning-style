# Test-Bed 2：中等任务双臂对照实验

## 实验设计
5个开放任务×2臂=10个空目录，覆盖：
1. Python游戏（Roguelike）
2. Web应用（白板）
3. 数据报告（股票回测）
4. CLI工具（Git）
5. 深度技术调研（AI Agent框架）

## 核心发现

### 1. 执行者一致评分：7.5-8分
5个A臂执行者都给skill打了7.5-8分——有用，但不是神。

### 2. 一致结论：skill不提升代码质量，提升交付可信度
所有执行者一致认为：
- 代码本体（架构、算法、功能覆盖）——和裸模型差不多
- 交付可信度（有没有真验证、有没有列未验证项）——带skill的明显更好

### 3. 最有用的规则
执行者一致认为最有用的规则是：
1. **全绿不算证据**——测试全过不代表没问题，故意做一次错误才算验过
2. **真打开看一眼**——真开浏览器看，抓到端口劫持、假完成

### 4. 5个执行者全部违反了"执行前先调研"
所有执行者都没做到"动手前先调研"，原因一致：
- 规则冲突——和"小且可逆直接做"打架
- 自包含任务——任务本身没引用外部事实，不用查

### 5. 一致建议：给"执行前先调研"加触发条件
执行者一致建议：
- 不是所有任务都要先调研
- 只有任务引用外部事实/有多个竞争选型时才需要
- 自包含构建任务可跳过

## 结论

**中等任务上，skill的价值开始体现。**

中等任务有一定复杂度，容易假完成——说自己做完了，其实没验证。
skill的价值就是防这个——逼你真验证，而不是"我觉得行"。

**但skill也有副作用。**

比如"执行前先调研"这条，执行者都觉得和"直接做"打架——这就是规则之间的冲突。
