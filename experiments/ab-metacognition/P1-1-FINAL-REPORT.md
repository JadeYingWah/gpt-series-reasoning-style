## 二、三个核心判定

### 2.1 skill 有效性：正向成立（+1.67 ~ +2.83）
在 n=3 代码类任务上，两个 skill 版本均高于无 skill 基线。收益来源（判分子跨组观察）：「范围外行为有声明 + UNVERIFIED 清单 + 反例可复算」是各组第一名的共性，而非探测通过数最高（T1-47 通过数最低 38/44 却并列第一——5 个失败项全部落在已声明设计决策内）。

### 2.2 原则引导 ≈ 硬指标（+1.17 在误差内）
结合反例执行率：**原则引导条件下反例验证执行率 4/4 = 100%**（T1 3/3、T2 22/22、T3 10/10 全部自发完成且含「变异体存活→补用例→复杀」过程留痕），硬指标条件也 4/4——**原则引导已实现硬指标想保证的确定性**。

### 2.3 v1.2.3 三项修订终局建议：**不实施硬指标化，保持 v1.2.2 原则引导**
- 等效性：+1.17 分差在判分误差内，无优越性证据
- 简洁性：v1.2.2 以更少条款达成同等确定性（原则引导的「通过率不是鉴别力」已足以驱动强模型自发反例验证）
- 可复算性范式已由执行侧以 reference 形式吸收（e691313）✅
- 保留意见：本实验全部为强模型单环境；「对弱模型可能显著」假设仍不可检验

## 三、判分子的跨组观察（7 条，全部有探测数据支撑）

1. **Windows 控制台编码是最高频真实崩溃源**：10 份中 4 份输出 emoji 抛 UnicodeEncodeError（T1 的 22/47/89、T3 的 39）；只有 3 份显式处理（34 的 reconfigure、57/58 的 UTF-8 字节写入）。Linux UTF-8 环境不可复现，对本机用户为真崩溃。
2. **第一名共性 = 声明完备而非通过率**：T1-47 探测通过数最低（38/44）却并列第一——5 个失败全部落在事前书面声明的设计决策内（str-only、未闭合容错、UTF-16 嗅探），客观扣分反而最低。
3. **静默数据改写是最贵缺陷类**：4 例（T1-22 引号内 CRLF→LF、T1-34 丢字符、T2-89 换行→空格已声明、T3-58 星号泄漏），**3 例当事人自测全绿未发现**，全部由独立探测/差分扫出——「只断言退出码与无栈泄漏无法覆盖此类，必须做输入保真度/往返一致性断言」。
4. **「声明与实现矛盾」同方向**：三例均为「声称宽松/保证，实现相反」（T1-34 声称宽松实则吞字符、T2-22 声称不复用 id 实则复用+恒真断言、T3-39 声称跨平台字节一致实则 GBK）。T2-22 的恒真断言（verify.py:249 对两种情形都为真）是「全绿但不鉴别」的教科书样本。
5. **可复算性整体健康**：10 份验证脚本全部干净环境复算成功、退出码与报告一致（−2.0 锚点零触发）。**判分者分歧注记**：上一轮判分子曾判 T1-22 的 bug_sweep.py 硬编码路径为破绽，本轮判分子判其可复算 ✓——两轮复算方式不同（本轮未触发该路径），此分歧如实记录不掩盖。
6. **变异/反例 10/10 全有且全为真实语义错误**（锚点 −1.5/−0.5 零触发）——四轮实验后反例验证已成强模型标配；质量梯度在于**是否留下「存活→补用例→复杀」过程证据**（4 份有，其余只有终局 100%）。
7. **规模与质量弱相关**：用例数 29-116 不等，客观扣分不单调（76 用例扣 4.0，47 用例扣 0）。决定性因素=覆盖面与盲区声明双向一致 + 自测是否覆盖 CLI/编码这条真实路径（T3-39 的 76 用例把 CJK/emoji 全留单元层、CLI 全 ASCII，恰好绕开唯一真缺陷）。

## 四、方法学沉淀（本轮新增）

1. **锚点 rubric**（基础分 50 + 七项客观扣分 + 两项主观）有效消除判分者权重漂移——上一轮两判分子排序完全反转的问题未再出现。
2. **单判分子原则**再次验证：10 份一人评完，尺度统一。
3. **执行者方差与判分者方差均大于版本差**——所有 A/B 结论必须「同执行者双组 + 单判分子 + 锚点 rubric」三件套才可信。
