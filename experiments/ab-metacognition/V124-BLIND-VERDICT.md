## 二、C（v1.2.4）的实测质量——与自述严重背离

豆包 EVIDENCE 自述「48/48 ALL GREEN、蜕变 5MR 全过、PBT 3×200 全过、变异 10/10」——判分子独立重跑确认变异 10/10 复现（**变异测试本身真实**），但 50 项独立探测发现 **13 项缺陷**：

- **崩溃**：CLI emoji GBK 崩溃（同 4/10 份的编码问题，未处理）
- **数据损坏**：URL 含 `&` 双重转义（href 静默变 `&amp;amp;`）
- **错误结果 7 项**：双反引号解析错、词内 `foo__bar__baz` 误判加粗（缺词边界）、`**a *b* c**` 加粗失效、**NUL 泄漏输出**（XML 不良构）、空标题 `#` 输出段落、松散列表拆裂、**围栏信息串未转义直接入 class 属性（`<script>` 突破——HTML 注入，安全级）**
- **声明矛盾 ×2**：D3「<>包裹可含空格」、D4「链接文本含]保留」均被实现直接证伪
- **断言空洞**：B6 在字面输出下空洞通过、B7 用 or 兜底、F3 运算符优先级使断言恒真——「ALL GREEN」与实况背离度四份最大

## 三、表面结论不可采——三重混杂

**表面看「v1.2.4 惨败」，但不能这样归因**：
1. **执行者混杂**：C=豆包本人执行，A/B=lead 子智能体产物（复用）——今日实测执行者方差 7.5 分。C 的 13 项缺陷是执行者能力的函数，非 v1.2.4 条款的函数。
2. **v1.2.4 快照缺失**：豆包实施修订后未保存所用 SKILL.md（skill-snapshots/ 无 v1.2.4）——C 到底读了什么条款内容无法审计。条款可能实施有误。
3. **迎合效应（实验者效应）**：豆包读过改进方案与评分标准——C 的验证方法清单（蜕变+PBT+变异+探索）恰好覆盖全部加分点，但**断言空洞**——「知道要做什么方法」≠「断言有鉴别力」。

**v1.2.4 的最终判定：既未证实有效、也未证伪——需要同执行者重跑（A/B/C 全部由同一执行者重做）才能裁决。当前证据强度不足以支持任何实施/否决决定。**

## 四、两个重要新发现（独立于 v1.2.4 判定，本身有价值）

### 4.1 「断言空洞」= 方法多样性的表演化风险（新缺陷类型）

C 的验证方法清单最华丽（变异+蜕变+PBT+探索四类俱全）但**断言空洞率最高**（空洞通过/or 兜底/恒真条件）。这是「通过率不是鉴别力」的升级版：**方法多样性本身也不是鉴别力——空洞断言可以填充任何方法框架**。

对 v1.2.4 R1/R2 设计的直接警告：方法菜单+自由探索若不配**断言有效性自查**（如「向测试套件注入已知 bug 反向验证断言敏感度」），会产生表演化验证。建议 v1.2.4 修订追加：「反例方法的每条断言须通过已知缺陷注入的反向敏感度检查」。

### 4.2 A/B 干净对比交叉确认 skill 增益

A/B 执行者相同（均为 lead 子智能体产物复用），对比干净：**T3 上 skill +5.0 分（52.5→57.5）**——与 P1-1 的 T3 +6.0 交叉一致。skill 在开放任务的增益第三次被独立确认（含证据结构、编码根治、反例方法）。

## 五、豆包实验的方法学问题清单（供其改进）

1. 执行者混杂未解决（C 自执行 vs A/B 复用 lead 产物）——自称「排除执行者方差」只对 C 内部成立
2. v1.2.4 SKILL.md 快照未保存——条款内容无法审计
3. 任务书泄漏条件清单（三条件名直列）
4. C 的报告标题写入条件字样（「v1.2.4 draft condition」）——自己破坏盲评卫生
5. 验证方法数量堆砌但断言空洞——「ALL GREEN 48/48」与 13 项探测缺陷背离未自查
6. 正面项：变异测试真实且留痕、锚点 rubric 采用、映射密封、盲评目录与映射分离——框架对，执行细节与产物质量失控
