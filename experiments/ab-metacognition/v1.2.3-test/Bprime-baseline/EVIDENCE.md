## 2. 实现要点

字符级单趟状态机 `parse()`，时间 O(n)，无回溯：

- 引号仅在**字段起始位置**才开启引用；字段中间出现的 `"` 是普通数据（故 ` "a"` → ` "a"`，与标准库一致）。
- 引号内：`""` → 一个字面 `"`；逗号与 `\n`/`\r` 均为数据。
- 行尾：`\r\n` 视为一个行尾，`\n`、`\r` 单独也可，允许混用。
- 文件以换行结尾时不产生尾部空行；末行无换行照常产出。
- 引号未闭合：按“到输入结尾自动闭合”容错处理，不抛异常（与 Python 标准库行为一致）。
- BOM：`parse_bytes/read_file` 按 BOM 推断编码（UTF-8 BOM / UTF-16 LE·BE），并剥离 BOM；无 BOM 默认 UTF-8，解码失败抛 `CsvError`。

命令行：`python csv_parser.py <file.csv> [--json] [--encoding ENC]`
解析结果写 stdout（每行一个 row 的 Python 字面量），`rows=N max_cols=M` 统计写 stderr；缺参数退出码 2，文件不存在/解码失败退出码 1。

## 3. 语义决策（可争议处已显式记录）

1. **完全空行产出 `[]` 而非 `['']`** —— 对齐 Python 标准库 `csv` 的默认行为；因此只含 `\n\n\n` 的文件结果是 `[[], [], []]`。
2. **空格即数据**：字段前后空格原样保留，不做 `strip`。
3. **未闭合引号不报错**，取到输入结尾。
4. 不支持自定义分隔符/引号符、注释行、反斜杠转义（任务书未要求）。
5. 引号内的 CRLF 原样保留为字段内容（RFC 4180 语义，非行尾）。

## 6. 不确定项 / 已知限制

1. 空行语义 `[]` 是与标准库对齐后的选择；若验收口径要求 `['']` 或“跳过空行”，属需求二义，需确认后一行可改（`parse` 中行尾分支）。
2. 无 BOM 的 UTF-16 不自动识别（按 UTF-8 解码可能不报错而产出乱码），需显式 `--encoding`。UTF-32 BOM 亦未处理。
3. 未实现流式读取：整文件一次性读入内存，超大文件（GB 级）不适用。
4. 未实现 CSV 写入/序列化，因此“解析→写出→再解析”的往返测试未覆盖，往返一致性未经证明。
5. 与标准库对拍时，BOM 由对拍前人工剥离（标准库 csv 本身不处理 BOM），BOM 行为改由显式期望与文件级用例覆盖。
