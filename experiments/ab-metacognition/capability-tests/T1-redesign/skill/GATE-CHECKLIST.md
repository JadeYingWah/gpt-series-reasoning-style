### 6. 最高影响问题（技术风险与已知权衡）

1. **技术栈选择直接影响可运行性和维护成本**：Node 生态 vs Python 生态，两者在本机均可用，但依赖安装、启动命令、前端集成方式完全不同。
2. **持久化方案的健壮性**：SQLite 文件型 vs 纯前端 LocalStorage — 后者满足"重启不丢失"但数据绑定浏览器，换浏览器/清缓存即丢失；前者是服务端持久化，更符合"数据持久化"的严格语义。
3. **前端复杂度**：原生 JS 无构建步骤但交互代码冗长；React/Vue 需构建工具链但组件化清晰 — 对"本地运行"门槛有直接影响。
4. **与 noskill 对照组的变量隔离**：若 skill 组采用与 noskill 组完全相同的技术栈，实验只能测量流程纪律差异；若采用不同栈，则混入技术栈变量 — 需用户裁决实验设计意图。

### 7. 推荐方案

**方案 A：Node.js + Express + SQLite + 原生前端**（详见 AB-PROPOSAL.md）

理由：①与 noskill 对照组同技术栈，实验变量纯净（仅流程纪律差异），符合 A/B 对照实验设计；②Node v22 已在本机验证可用，依赖安装已跑通；③Express+SQLite 是 Todo App 最经典组合，搜索结果中多篇采用；④原生前端无构建步骤，本地运行门槛最低。

### 8. 其他选项（已评估并否掉，信息性）

- **PocketBase 单文件后端**：零后端代码，但需下载二进制文件，且后端逻辑不可定制，不利于展示完整工程实现；否掉。
- **纯前端 + LocalStorage**：满足最低持久化但数据不跨浏览器，且无服务端 API，与"Web 应用"通常含服务端的预期不符；否掉。
- **React + Express + MongoDB**：功能最强但需 MongoDB 服务和构建工具链，超出"单项目本地运行"的简洁要求；否掉。
- **Java Spring Boot**：过重，启动慢，依赖 JDK，本机未验证 JDK 可用性；否掉。

### 14. 完成标准与失败行为

**完成标准（可检查）**：
- [ ] `npm install` / `pip install` 无报错，依赖安装成功
- [ ] `npm start` / `uvicorn` 启动后终端输出服务地址，无崩溃
- [ ] 浏览器打开地址返回 200，页面渲染完整，无控制台 JS 报错
- [ ] POST 创建待办 → 201，数据可在 GET 列表中查到
- [ ] PATCH 切换完成 → completed 字段正确翻转
- [ ] PUT 更新 → 字段正确更新
- [ ] DELETE 删除 → 条目消失，再次查询返回 404
- [ ] 停止服务后重启，之前创建的数据仍然存在（持久化验证）
- [ ] 空标题提交返回 400 错误，不写入数据库
- [ ] 中文标题/描述正确存储和显示（UTF-8 验证）
- [ ] README 包含运行步骤和验证说明
- [ ] 证据报告附可复现验证命令

**失败行为**：
- 依赖安装失败 → 重试 1 次，仍失败则切换备选技术栈并触发重新确认

- 超过 3 轮修复仍有端点失败 → 上报并请求裁决

**停止条件**：所有完成标准项通过或明确标 UNVERIFIED 后停止，不无限迭代 UI 细节或添加未要求功能。
