## 一、方法总目录（10 种，按本实验适配度排序）

### 第一梯队（对 AI 单文件/小型交付直接可用，本轮实验已验证或强适用）

**1. 参考实现差分（Differential Testing）**【已实证】
- 原理：与标准库/成熟实现/上一版本对随机与边界输入逐字符对比
- 本轮证据：T1-B′ 3000 例差分、红队 6 万/12 万轮 fuzz 对比 stdlib——**唯一抓到静默数据改写的方法**
- 适用：有标准库/参考实现的场景（CSV/JSON/MD/编解码/排序/序列化）
- 局限：无参考实现时不可用 → 用 #5 蜕变测试补位

**2. 变异测试（Mutation Testing）**【已实证】
- 原理：源码注入单行语义错误，验证测试套件变红（杀伤率=测试鉴别力）
- 本轮证据：skill 臂 6/6 自发完成且全真实语义变异；mutmut/cosmic-ray 可用；「MT 迫使代码最小化」是额外收益（mutmut 作者经验）
- 适用：已有测试套件的鉴别力自证；MT 白盒、空间有限、可知道何时完成
- 局限：只证「测试有鉴别力」，不直接发现新 bug

**3. 属性测试（Property-Based Testing，PBT）**【新发现，强烈推荐】
- 原理：定义「对所有输入都成立的性质」（非具体输入输出对），框架（Python: **Hypothesis**；JS: fast-check）自动生成大量随机输入（含退化用例：空/单元素/重复/超大）验证性质
- 经典性质：**往返一致**（serialize→deserialize=恒等）、**幂等**（sort 两次=sort 一次）、**守恒**（输出包含且仅包含输入元素）、**单调性**、概率和=1
- 本轮适配示例：T1 CSV——任意字节串 b，parse(b) 再序列化往返不丢信息；T2 todo——任意操作序列后 list 输出与文件内容一致；T3 md2html——输出恒为良构 HTML（T3 无 skill 臂已自发用 xml.etree 做了，是 PBT 的不变量特例）
- 与本轮 R3 的关系：**「输入保真度/往返断言」就是 PBT 的一个性质实例**——PBT 是它的框架化与自动化
- 工具：Hypothesis 零成本可用（本机环境已具备 Python）

**4. 蜕变测试（Metamorphic Testing，MT）**【新发现，解决无 oracle 场景】
- 原理：定义**蜕变关系 MR**（「输入按 X 方式变换，输出应如何变化」），验证关系成立——**不需要预期输出，解决 test oracle problem**
- MR 六类：增加 / 减少 / **不变性** / 排列 / 反转 / 包含
- 本轮适配示例：T1 CSV——①不变性：同一文件解析两次结果必须相同（幂等）②排列：交换两列数据，各字段值应保持逐字段对应；T3 md2html——①不变性：同输入两次转换输出逐字节相同②增加：正文追加段落，已有部分的 HTML 必须逐字节不变（**这个 MR 恰好能抓 T3-58 的占位符串号 bug**——追加段落改变全局编号导致前文输出变化即红）；T2 todo——增加：多加一条待办，其余条目的 id 与内容必须不变（**这个 MR 能抓 T2-22 的 id 复用 bug**）
- 关键价值：**无参考实现/无标准答案的场景**（自定义算法、创意产出、ML 输出）也能系统化测试——差分法的补位方法
- LLM 时代的研究（arXiv 2605.13898 综述）：MR 可由 LLM 自行推导（CodeMetaAgent 用 MR 变换输入探索推理路径一致性来自校正，**无需 ground truth**）；MR-check 反馈循环已是自校正机制
- 限制：MT 验证一致性而非正确性（可以一致地错）；MR 设计需要领域知识；关系写错会产生假发现

**5. 不变量检查（Invariant Checking）**【半新——T3 无 skill 臂已自发使用】
- 原理：输出的结构性质恒成立（XML/HTML 良构、标签配平、数字守恒、无孤立符号）
- 本轮证据：T3-39 用 xml.etree 良构解析 + 标签配平（40 探测 0 bug 的贡献者）
- 适用：任何有结构约束的输出（HTML/JSON/XML/SQL）

### 第二梯队（特定场景）

**6. Golden Master / 快照测试**：记录基线输出，变更后对比——适合回归场景，一次性 AI 任务意义有限；注意基线存「验收标准」而非「预期字符串」（非确定性输出用 criteria 而非 exact match）

**7. 对抗输入攻击（Adversarial Input）**【已实证】：畸形/极端/恶意序列（T3-39 的 2000 个 `*`、60 层嵌套；T2 的 JSON 五种损坏形态）

**8. 探索式测试（Exploratory Testing，SBTM）**：即 R2「自由探索配额」的方法学名——同时学习+设计+执行，靠测试者直觉发现脚本外缺陷；session-based 记录

**9. 错误注入（Fault Injection / Chaos）**：对运行环境的故障注入（断电/断网/损坏文件）——T2 各臂的「损坏 JSON 不崩」已是其简化形态

**10. 静态分析**：语法/类型/lint（py_compile 已在各臂使用；AST 自证无 import csv 是 110 号的创造性用法）

### 不适用/低优先（记录排除理由）

- **符号执行**：需要重型工具链，单文件任务性价比低
- **Contract Testing**：多服务架构场景，AI 单文件任务无此结构
- **VCR/回放测试**：第三方 API 交互场景，本系列无
- **视觉回归**：GUI 任务可用（Playwright 截图对比），数据/代码任务无

## 二、方法选择的决策树（可直接写进 skill）

```
有参考实现（标准库/成熟库/上一版）？
├─ 有 → 差分测试（首选，抓静默损坏最有效）
│        + 变异测试（自证测试鉴别力）
└─ 无 → 输出有结构约束？
         ├─ 有 → 不变量检查（良构/配平/守恒）+ PBT（性质自动生成）
         └─ 无 → 蜕变测试（定义 2-3 条 MR：幂等/排列/增减关系）
全部场景叠加：对抗输入 + 往返一致性（I/O 类）+ 自由探索（R2 配额）
```

## 三、对本轮实验的复盘意义

1. **T2-22 的恒真断言**：若用 PBT 思路（性质：删除后新增的 id 必须大于所有现存 id）而非写死 `[1,2]`，恒真问题不可能发生——**性质断言天然防恒真**。
2. **T3-58 的占位符串号**：若用 MR「追加段落，前文输出逐字节不变」，单测全绿会被立即打破——**MR 检查的是全局一致性，恰好覆盖「单测用例各自独立」的盲区**。
3. **T1-22 的静默 EOL**：差分已证有效；MR「CLI 输出 = parse() 输出的 repr」这条关系也能抓（库与 CLI 不一致即红）。
4. 结论：**MR/性质的另一个价值 = 打破「用例各自独立」的结构盲区**（跨用例/跨层的一致性是用例级测试天然测不到的）。
