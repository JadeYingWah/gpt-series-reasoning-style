## 一、只有实验者知道的观察（判分报告之外的）

1. **T1 原则臂多花的 300k token 去向可精确归因**：1075k（原则）vs 775k（B′）差值的大头不是「填表格」——是**证据骨架工程**：evidence/ 目录搭建、可复算性设计（相对路径/tempfile/编码处理）、变异脚本从零编写。109/119 两个判分子都确认其可复算性满分——这 300k 买到了「第三方零成本验收」，不是浪费。**ANALYSIS-RECORD 3.5「流程 ≤15%」的推测需要先做 jsonl token 去向分解再定**（我倾向：流程声明实际占比远低于 15%，骨架工程占大头且物有所值）。

2. **T2 硬指标臂跑了 86 分钟（全场最长）**：15 个变异体逐个注入-验证-恢复。原则臂做了 22 个变异反而更快（约 40 分钟）——因为原则臂把变异并入主验证脚本一次跑完，硬指标臂按条款**独立成脚本+对照组分离**。这提示：**硬指标的独立成脚本要求有真实时间成本**，但其产物（mutation_check.py 可独立复跑）是验收资产。

3. **「超配溢出」现象**：T1 原则臂（轻量档）自发执行了 A2+ 才必选的第五增强点（覆盖面枚举+盲区自查）；T2/T3 的原则臂同样做了硬指标组的变异测试。**条款间存在「溢出效应」——读到 A2+ 条款的执行臂把纪律扩散到了非必选行为**。这是 v1.2.2 原则引导 efficacité 的深层原因之一：原则不是最低要求而是「基调」。

4. **两个真实的环境挣扎样本**（harness 鲁棒性）：M2/T2 硬指标臂遇到 bash stdout 捕获失效，自发改用「命令写文件 + Read 读取」通道完成全部验证并诚实披露；120 号红队同样自改通道。**skill 的「不阻塞/绕行+披露」条款在这两次真实故障中都被正确执行**——条款在异常场景下的表现比正常场景更值得记录。

5. **T3 三臂在两个决策点上的行为分化**（功能完整度的分水岭）：①嵌套列表：无 skill 降级+声明，两个 skill 臂都实现；②「简化须声明」：无 skill 臂的降级声明是被动应答式的，skill 臂的实现决策带「范围克制但目标所需主动处理」条款的痕迹。**skill 影响了「多做一点还是少做一点」的默认选择方向**——这比验证形式差异更接近「产出质量」的本质。

## 二、对 ANALYSIS-RECORD 六条改进的逐条裁决（实验者视角）

| # | 建议 | 我的裁决 | 依据 |
|---|---|---|---|
| 3.1 门禁按规模精简 | **部分前提不成立**：T1/T2/T3 全部是轻量档——skill 臂已经在走 **5 字段精简门禁**（不是 14 字段）。「轻量任务门禁 14→5」早已是 skill 现状。真正可精简的是**声明性输出的措辞密度**（产物优先条款要求「能一行不两行」，但 jsonl 显示门禁声明仍偏长） | 采纳方向、修正前提：目标从「字段数」改为「每字段 token 预算」 | jsonl 行为链 |
| 3.2 反例方法菜单 | **强烈同意，本轮最强改进**：三任务 skill 臂 6/6 全做变异测试、0/6 做 fuzz 差分；而 B′ 与两个红队全靠 fuzz 差分抓到静默损坏。skill 条款中「变异测试」作为示例造成了**方法窄化 bias**（条款没禁止 fuzz，但示例引导了选择） | 第一优先级 | 判分子+红队双确认 |
| 3.3 消除门槛心理 | **证据较弱**：「达到即停止」是推论——实测反例：T2-34 发现 m09 存活后未停止而是加严复杀；T3-58 单测全绿后仍做 CLI 冒烟。观察到的真实提前停止是 Medium 第 2 轮的覆盖收窄（弱信号） | 低优先级，并入 3.6 | 实验在场观察 |
| 3.4 深度优先于广度 | **同意结论，修正机制**：「先判断 3 个最高风险路径」需要领域知识，skill 无法内置——可操作化版本是「验证组织元原则：先问『这个功能最可能在哪条真实路径上坏掉』（如 I/O 编码/持久化往返），再做广度枚举」 | 中优先级 | 判分子观察 ⑦ |
| 3.5 token 预算 | **有保留**：3.5 的「流程 ≤15%」是推测——实测多出的 token 主要花在证据骨架工程（见观察 1），非表格填写。先做 jsonl token 去向分解，再决定是否需要预算条款 | 先测量后设计 | 待做的 jsonl 分析 |
| 3.6 自由探索配额 | **最有价值的建议**：B′ 的 3000 fuzz、红队的 12 万 fuzz 全是自由探索产物；skill 臂 0/6 做 fuzz——流程确定性挤掉了探索性验证。「最低要求完成后 10-15% token 自由探索」直接针对本轮发现的最大质量损失源 | 第一优先级（与 3.2 并列） | 判分子+红队双确认 |

## 三、我的补充改进（ANALYSIS-RECORD 未覆盖，全部有实验证据）

1. **输入保真度/往返一致性断言**（最高优先级）：本轮最高频贵缺陷是**静默数据改写**（4 例：CLI EOL 翻译、丢字符、换行→空格、星号泄漏），3 例自测全绿未发现。代码类核心验证应加一条：「对 I/O 类功能做 输入→处理→输出→再输入 的往返一致性断言，且断言不得对多种行为同时为真（防恒真断言，T2-22 教训）」。
2. **CLI/编码真实路径实测**（第二优先级）：10 份中 4 份 Windows 编码崩溃，全部在自测盲区。代码类验证加：「CLI 在剥离 PYTHONUTF8/PYTHONIOENCODING 的干净环境下实测非 ASCII 输出」（P1-2 判分子实测方法）。
3. **反例过程留痕制度化**（中优先级）：质量梯度在「变异体存活→补用例→复杀」过程证据（4 份有、6 份无）——v1.2.3 的方向在这一个小点上仍有价值，可轻量吸收为「反例验证须记录发现与修复过程」。
4. **保留 v1.2.3-draft 快照不删除**（零成本）：全部实验为强模型，「硬指标对弱模型可能显著」假设未检验——draft 快照是未来弱模型实验的现成装置。
5. **证据骨架工程的性价比确认**：skill 臂多花的 token 买到「第三方零成本验收」（两代判分子都靠 evidence/ 快速定位）——**这条不该被 3.5 的预算条款误伤**。

## 四、skill 定位的重新表述（实验者总结）

本轮五轮实验（Stage1/2、v1.2.3、P1-1/P1-2）对 skill 的定位收敛为一句话：

> **skill = 确定性层 + 结构层 + 校准层（已实证有效）；缺失的是探索层；多余的是硬指标层。**

- 确定性层：反例执行率 33%→100%、evidence/ 0%→100%、缺口率 100%→33%
- 结构层：第三方验收效率（判分子靠 evidence/ 与可复算脚本快速工作）
- 校准层：声明完备性（第一名共性）
- **探索层缺失**：流程确定性挤掉了自由探索（fuzz/差分）——B′ 与红队的优势所在，改进 3.2+3.6 直指此处
- **硬指标冗余**：原则引导已达成同等确定性（P1-1 判定维持）

## 六、实验过程自我批评（实验者义务）

1. 我中途注入变更（M2/M3）与 spawn 时序失误（120 目标错位、双臂撞车）——流程管理有改进空间，但均被设计冗余吸收（追加任务+work-A2 隔离）。
2. n=3 样本的统计功效弱（+1.17 的等效判定在 n=3 下置信度有限）——v1.2.3 判定标注了「判分误差内」，如需更强结论需扩 n。
3. 全部单环境单模型（强模型），「对弱模型有效」假设始终未检验。
4. 判分子 119 对 T1-22 bug_sweep 可复算性的判定与 109 相反（复算路径差异）——判分者间分歧仍存在于个别事实认定，锚点 rubric 只解决了权重漂移，事实认定分歧需双判分对照。
