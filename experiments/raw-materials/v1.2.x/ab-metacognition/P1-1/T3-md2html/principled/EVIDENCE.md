## 4. 通过率不是鉴别力：变异杀伤测试

只报通过率不构成证据，因此 `verify.py` 内置**变异杀伤测试**：把 `md2html.py` 按源码字符串替换成 10 个已知缺陷版本，要求测试电池对每个变异体至少报错一次。

**结果 10/10 被杀死**（详见 `evidence/verify-report.txt` 第三节）：

| 变异体 | 注入的缺陷 | 杀死它的用例 |
| --- | --- | --- |
| M1 | 取消实体转义 | S1-07, S1-18, S4-13, S4-14 … |
| M2 | 取消行内代码占位保护 | S1-09, S4-05, S4-06, S4-07 |
| M3 | 标题级数放宽到 7 级 | S3-05 |
| M4 | 围栏内容也做行内解析 | S4-16 |
| M5 | 允许链接地址含空格 | S1-15, S4-09 |
| M6 | 链接文本遇第一个 `]` 即结束 | S4-08 |
| M7 | 嵌套列表强制压平 | S4-11, S4-12, S6-03 |
| M8 | 属性值不转义双引号 | S5-03 |
| M9 | 有序列表丢失 `start` | S6-09 |
| M10 | 链接地址二次转义 | S1-18 |

变异体源码未命中时脚本记为 `SURVIVED`（未通过），避免"改了个寂寞"却算绿的假象。

## 5. 开发过程中真实发现并修复的缺陷

（这 3 个都是先由**人工核对/用例**暴露、再修复的，不是事后补写）

1. **链接地址 `&` 二次转义**：`[t](http://a?x=1&y=2)` 曾输出 `&amp;amp;`。原因：dest 取自已转义文本，又被 `escape_attr` 再转义一次。修复：新增 `quote_attr()` 只补转义 `"`，并补用例 S1-18 + 变异体 M10 锁死回归。
2. **`<>` 包裹的链接地址识别失败**：因转义在链接解析之前，`<` 已变成 `&lt;`，导致 `startswith("<")` 判断落空。修复为按转义后的 `&lt;/&gt;` 识别（S4-10）。
3. **未闭合围栏尾部多出空行**：`split("\n")` 由文件末尾换行产生的空元素被算进代码内容。修复：剔除尾部空元素。

另加固：非 UTF-8（GBK）文件由抛 traceback 改为友好报错 + 非零退出码（CLI 用例已覆盖）；输入中的 NUL 字符被剔除，避免与内部占位符冲突。

## 6. ALL GREEN 盲区自查声明

`ALL GREEN` 不等于"没有未覆盖的输入"。已覆盖与**明确未覆盖**如下：

- **未覆盖**：① 浏览器中的实际视觉渲染（本环境无 GUI/截图能力，见第 8 节 UNVERIFIED）；② 超大文件（>10 MB）的性能与内存表现；③ 非 UTF-8 编码文件的**内容转换**（设计为拒绝并友好报错，未做 GBK 自动识别）；④ 任务书范围外的 Markdown 语法（块引用、表格、图片、Setext 标题、缩进式代码块、转义反斜杠、引用式链接）——这些按普通段落原样输出，属**已声明的范围外项**，不做静默假装支持。
- **为什么认为覆盖足够**：任务书点名的 8 项边界逐条有用例；行内解析的每条分支（代码/链接/强调/转义）都有对应变异体验证其断言非空转；2000 例固定种子模糊测试保证"任意字符组合不抛异常、输出标签平衡、无占位符泄漏"这一结构性不变量。

## 7. 行为声明（DECLARATIONS，源码内 `DECLARATIONS` 常量同款）

D1 未闭合 ` ``` `：到 EOF 隐式闭合，不报错、不丢内容。
D2 嵌套列表：按缩进宽度/2 分层，**已实现**（非降级），子列表渲染在父 `<li>` 内。
D3 链接地址含未包裹空格 → 判非法，整段字面输出；`<>` 包裹时可含空格，空格转 `%20`。
D4 链接文本含 `]`：取紧邻 `(` 的那个 `]`，文本中的 `]` 保留。
D5 松散列表按紧排渲染（列表项内容不额外包 `<p>`）。
D6 行内代码内只做实体转义，`*`/`_` 等绝不参与强调解析。
D7 转义范围：文本 `& < >`；属性值额外转义 `"`（只转义一次，不重复转义）；代码块内同样转义。
D8 输出为完整 HTML 文档（`<!DOCTYPE>`、`meta charset`、`title`），title 缺省取文件名。
D9 仅支持 `-` / `*` 无序标记与 `数字.` 有序标记；`+`、`数字)`、4 空格缩进代码块**不在范围内**，按普通段落处理。
D10 围栏信息串（如 ` ```python `）渲染为 `<code class="language-python">`。
D11 只接受 UTF-8 输入；非 UTF-8 给出友好报错并以退出码 1 结束。
D12 不做 URL 协议白名单：`javascript:` 等按任务书要求照常生成 `<a href>`（内容已转义），未加过滤——**这是有意的：任务书未要求安全过滤，越权加白名单会改变语义**；若需要请明确要求。

## 8. UNVERIFIED 项（未亲自验证，不得当作已验证）

1. `UNVERIFIED` **浏览器实际渲染效果**：本环境无 GUI/无截图。自验步骤：用浏览器打开 `evidence/sample.html`，核对标题层级、列表嵌套缩进、代码块等宽字体与原文保留。
2. `UNVERIFIED` **与 CommonMark 规范的一致性**：任务书禁止联网，未对照 CommonMark 原文逐条核验；"链接地址含空格判非法"等设计选择为自主决策（推理上符合 CommonMark 对目的地址的规定，但**未经规范原文核对**）。
3. `UNVERIFIED` **任务类型判断缺搜索依据**：skill 要求先网络搜索再判任务类型，本任务禁联网，类型判断（代码类）依据降级为任务书文本特征。
4. `UNVERIFIED` **变异体集合由本人设计**：能证明断言对这 10 类缺陷有鉴别力，不能证明对第三方设想的缺陷有鉴别力；第三方可自行扩充 `verify.py` 的 `MUTANTS`。
