## 3. 实现要点

```
python todo.py add "标题"    # 新增（自增 id，默认未完成，记录创建时间）
python todo.py done <id>     # 标记完成
python todo.py list [--all]  # 列出未完成（默认）/ 全部（--all），表格对齐
python todo.py rm <id>       # 删除
```

- 数据文件：默认与 `todo.py` 同目录的 `todos.json`，首次写入时自动创建；
  支持环境变量 `TODO_FILE` 覆盖（验证脚本据此做用例隔离，不污染任何既有数据）。
- JSON 结构：`[{"id":1,"title":"买牛奶","done":false,"created_at":"2026-09-13T20:42:23+08:00"}, ...]`，
  `ensure_ascii=False` + `indent=2`，中文原样落盘，便于人读与 diff。
- 写入用「临时文件 + `os.replace`」原子替换，避免写一半留下损坏文件。
- id 取「现存最大 id + 1」，删除后不复用旧 id。
- 表格宽度按 `unicodedata.east_asian_width` 计算（CJK / 全角 / emoji 记 2 列宽），
  零依赖实现对齐；标题中的换行、制表符在表格里显示为 `\n` `\t`，存储数据不受影响。
- 退出码：`0` 成功，`1` 运行期错误（id 不存在），`2` 用法错误（空标题 / 非整数 id / 未知命令）。

## 7. 不确定项与已知限制

1. **超长标题的取舍**：任务书只说要「处理」500 字符标题。我选择「完整存储 + 仅显示截断（40 列 + `…`）」，
   而非拒绝超长输入。若期望的是「超过 N 字符拒绝」，这是一处需求歧义，可一行改动适配。
2. **列宽算法**：按 `east_asian_width ∈ {W,F}` 记 2 列宽的通行规则。极少数新 emoji / 组合字符
   在个别终端下仍可能差 1 列（无第三方 `wcwidth` 无法做到 100%），零依赖前提下的已知取舍。
3. **标题含 `|`**：仅影响表格观感，不转义，不影响数据正确性。
4. **损坏文件备份**：只保留一份 `todos.json.bak`，重复损坏会覆盖上一份备份。
5. **未做并发/多进程写锁**：单用户 CLI 场景未纳入，若需可加锁文件。
6. **未覆盖**：非 UTF-8 编码的 `todos.json`（如 GBK 落盘）、文件系统权限不足、超大规模（万条）性能。
