## 最高影响问题（技术风险与权衡，供判断，不是提问）
1. 中文编码：SQLite默认UTF-8，但需确认前后端编码一致
2. 并发：SQLite写锁在高并发下有性能问题，但单用户待办应用无影响
3. 端口冲突：默认3000端口可能被占用，需支持环境变量配置

## 推荐方案
- 后端：Node.js + Express（轻量、生态丰富、与前端JS统一）
- 数据库：SQLite（better-sqlite3）（文件型、零配置、无需额外服务）
- 前端：原生HTML/CSS/JS（无构建步骤、express.static直接托管）
- API设计：RESTful 6端点（GET列表/GET单个/POST创建/PUT更新/PATCH切换/DELETE）

## 其他选项（已评估并否掉，不需要你选）
- React + Express + MongoDB：组件化好但构建复杂，单项目过度工程
- Flask + SQLite + Vue3：Python后端但需前后端分离部署，增加复杂度
- localStorage纯前端：无后端，不满足"数据持久化（重启不丢失）"的服务器端要求
