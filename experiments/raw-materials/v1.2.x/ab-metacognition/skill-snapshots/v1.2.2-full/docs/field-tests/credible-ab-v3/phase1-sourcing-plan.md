## 一、设计输入（Phase 0 的四条教训）

1. **D1 类简单精确任务无鉴别力**（三臂客观全对、盲评分差 ≤4）：Phase 1 任务必须留有"干预可生效的空间"——开放方法、不完整规格、隐藏边界情况。
2. **客观判据是最强区分器**（D3 的 recall/precision 差直接造成 37 分总分差）：新任务必须配可冻结的客观真值。
3. **任务书逐口径消歧**（D2-Q3"有效交易数"歧义教训）：规格中每个统计口径必须唯一化。
4. 后处理管线（冻结→spawn wrapper→审计→匿名化→盲评→仲裁）已验证可复用，直接承载 n=3。

## 二、任务类型与来源候选（外部 sourcing，全部公开源 + SHA256 冻结）

### T-A 代码类 × 3 任务

客观真值 = 冻结测试文件（SHA256），得分 = 测试通过率。判分区分点：任务书**刻意不给完整规格**，边界情况藏在测试集——验证干预应表现为 A 臂主动发现边界。

| # | 候选 | 来源（公开） | 客观真值 |
|---|---|---|---|
| T-A1 | 实现 Crockford Base32 编解码 | spec 官方页 + 公开 test vectors | 官方向量集逐条比对（含易错边界：排除 I/L/O、连字符、checksum 可选） |
| T-A2 | JSON Schema 子集校验器 | JSON-Schema-Test-Suite（官方公共测试集，MIT） | 冻结其官方测试文件子集，通过率计分 |
| T-A3 | 真实仓库小 bug 修复 | MIT/Apache 中型仓库的 minor/good-first-issue（候选 2-3 个备选，选定后 commit 级冻结） | 该 bug 的回归测试通过 = 修复成功 |

### T-B 创意/图形类 × 3 任务

客观份额弱化（权重调整见第四节），但保留**可脚本验证的几何/规格约束**作客观真值。

| # | 候选 | 来源 | 客观真值 |
|---|---|---|---|
| T-B1 | SVG 机械图：两齿轮纯滚动 + 曲柄滑块 | 自制机械审计方法论（几何闭式解可验算） | 冻结规格（齿数比、纯滚动约束、行程），脚本从 SVG 坐标验算几何一致性 |
| T-B2 | 指定状态机交互 widget（购物车下单流） | 规格自拟并冻结 | 冻结覆盖清单：状态数/迁移边/边界输入行为逐项核验 |
| T-B3 | 指定数据集可视化 | 冻结 CSV（来源同 Phase 0 数据池风格，另行选定） | 数据点存在性 + 轴保真（极值/刻度/单位）脚本核验 |

## 三、执行设计（批复后启动）

- **规模口径**：协议总设计 3 类型 × 3 任务 × 3 臂 = 27 次；Phase 0 已完成数据类 9 次，Phase 1 = 代码类 9 次 + 创意类 9 次 = **18 次执行**（n=3 指类型级 3 个独立任务，与协议一致）。
- 复用 Phase 0 全管线；speed FLAG、隔离白名单直接沿用。
- **匿名化修复**：复现命令统一改写为相对路径（Phase 0 漏洞项）。
- 预估 token 预算：T-A 约 3-4M、T-B 约 2-3M，合计 ≈6-7M（约为 Phase 0 的 1.5×）。

## 四、随方案呈批的权重调整（仅 T-B 创意类）

- 可验证性 15 → **25**（创意类"验证"权重相应上调）
- 其余三维不变；T-A 沿用 100 分制不变。
