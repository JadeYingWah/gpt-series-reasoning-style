## 一、要回答的问题

Phase 0 与 P1-1 的数据显示：skill 相对无 skill 有正向收益（+1.67~+2.83 分），但**档位之间（轻量/中等/重型）谁最优从未被测过**（中等档行为指纹在 Stage 2 已验证存在，但质量差异未测）。P1-3 回答：**多文件任务上，升档（轻量→中等→全流程）带来的质量增益是否抵得上 token 成本增长？**

## 二、「最优」的判据框架（需总指挥确认权重）

单一分数无法定义最优，提供三维数据由总指挥定权重：
1. **质量分**：锚点 rubric（同 P1-1：基础 50 − 客观扣分 + 主观两项）
2. **token 成本**：jsonl 实测（input+output+reasoning 求和）
3. **效率比**：质量分 / 万 token（或总指挥指定的其他函数，如「质量不低于某阈值前提下的最低成本」）

**须批复**：①是否接受三维并列呈现（推荐——避免预设权重）②是否需要「质量阈值」约束（如 ≥55 分才进入效率比较）

## 三、实验设计

- **任务**：1 个多文件任务（建议：三文件日志分析工具集——解析/统计/报告生成+共享数据层，比 M1 笔记工具复杂一档，足以拉开档位差异）
- **三臂**：轻量配置 / 中等配置 / 全流程（重型），skill 快照统一 v1.2.2（已发布版）
- **同执行者**：lead 子智能体 ×3（铁律）
- **判分**：单判分子 + 锚点 rubric + 独立探测 ≥30 项（复用 P1-1 方法）
- **样本量**：n=1 起步（每臂 1 次，共 3 次执行）；如结果方向一致可扩 n=3（9 次）
- **预计成本**：首轮 3 次执行约 200-400 万 token（全流程臂会显著高于轻量臂）

## 附录：先验预估（基于 Phase 0 已有数据，帮决策是否值得跑）

Phase 0 已有两次「轻量 vs 全流程」的直接对照（100 分制）：

| 任务 | A2 轻量 | A1 全流程 | 全流程增益 | A1 成本倍数 |
|---|---:|---:|---:|---:|
| D2 咖啡（数据+多口径） | 94.0 | 96.0 | +2.0 | ~2.3× |
| D3 时序（开放检测） | **85.8** | 78.9 | **−6.9** | ~2.7× |

两个先验信号：
1. **全流程的质量增益不稳定**（+2.0 与 −6.9）——D3 上全流程因「广撒网」反而拉低精确率（18 区间 vs 3 区间）。多文件任务上「升档」不保证更好。
2. **成本稳定 2-2.7×**——若 P1-3 结果重复此模式，结论大概率是「中等档是多文件任务的性价比最优，全流程仅在高风险/安全关键场景值得」。

预估结论：**首轮 n=1（3 次执行）的边际信息量有限**——Phase 0 已给出方向性先验，P1-3 的主要价值在「多文件+需维护」这个 Phase 0 未测的任务形态上。若预算紧张，可将 P1-3 降级为「1 任务 × 中等 vs 全流程两臂」（省掉轻量臂，轻量基线可由 M1 数据近似），预算减至 ~150 万。

由总指挥定夺：①全三臂 n=1（200-400 万）②两臂精简版（~150 万）③搁置待更多预算。
