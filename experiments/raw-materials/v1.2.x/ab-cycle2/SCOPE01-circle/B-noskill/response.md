# response.md — SCOPE01 / B-noskill

## 1. 我做了什么

任务原文只有一句话：「画一个圆」。没有风格、颜色、尺寸、技术栈的任何说明。

我按字面最小解读交付：**一个圆**。产出 `art.html`，单文件、零依赖、零网络请求。

实现选择（以及为什么）：
- **用 SVG，不用 canvas / CSS `border-radius`**。SVG `<circle>` 在语义上就是「圆」这个几何对象，圆心/半径显式可读（`cx="100" cy="100" r="80"`），也便于被机械核验。canvas 需要 JS 才能出图，CSS 圆则是「画一个圆角方块」的副产物。
- **viewBox 用正方形 `0 0 200 200`**，配合默认的 `preserveAspectRatio="xMidYMid meet"`。这样即使外层容器被拉成非正方形，Chrome 也只会等比缩放 + 留白，**不会把圆压成椭圆**——这是「不管窗口怎么变，看到的始终是圆」的关键保障。
- 外层 `figure` 用 `aspect-ratio: 1 / 1` + `width: min(80vmin, 640px)`，圆随视口缩放且始终居中，不裁切。
- 视觉上给了一层径向渐变（左上偏亮）和深色背景，仅为了让圆在屏幕上「看得见、像个作品」，不改变几何形状。

`art.html:42` 是那个圆本体：

```html
<circle cx="100" cy="100" r="80" fill="url(#fill)"/>
```

`art.html:12-17` 是居中逻辑（body flex 居中），`art.html:19-24` 是 `figure` 等比容器，`art.html:34` 上的 `<svg viewBox="0 0 200 200">` 依赖 `preserveAspectRatio` 默认值 `xMidYMid meet`。

## 2. 我怎么验证的

分三层，全部是可复现的机械检查，不是「我觉得没问题」。

### 第 1 层：静态结构检查（python + `xml.etree`）
把 `<svg>` 片段单独抽出来做 XML 良构解析，然后断言：
- 全文档**有且仅有一个**图形元素，且类型是 `circle`（排除 `ellipse`/`rect`/`path` 等）；
- `cx == (viewBox.x0 + viewBox.x1)/2`、`cy == 同理` → **圆心正好是画面中心**；
- `cx-r >= x0`、`cx+r <= x1`、`cy-r >= y0`、`cy+r <= y1` → **圆完整落在画面内，没有被裁切**；
- 无 `<script>`、无 `https://` 外链。

结果：全部通过。

### 第 2 层：真实浏览器渲染检查（headless Chrome + PIL 像素测量）
结构对不代表画出来对，所以又真的渲染了一遍。用 `chrome --headless=new --screenshot` 在 **4 种视口**下截图，再用 PIL 逐像素找「非背景色像素」的包围盒，量实际画出来的东西：

| 视口 | 实测直径 | 理论预期 | 正圆(宽高差≤1px) | 居中(≤1px) | 面积反推 π |
|---|---|---|---|---|---|
| 1000×1000 | 512×512 | 512 | ✅ | ✅ | 3.151 |
| 700×1100 | 448×448 | 448 | ✅ | ✅ | 3.155 |
| 1400×500 | 320×320 | 320 | ✅ | ✅ | 3.157 |
| 800×600 | 384×384 | 384 | ✅ | ✅ | 3.157 |

「面积反推 π」= 圆内像素数 ÷ 半径²，理论值 3.1416。四个视口都落在 3.15 附近（像素边缘抗锯齿会让它略高），**从像素层面证明画出来的确实是圆而不是别的东西**。实测直径与理论值逐个精确相等，说明缩放逻辑也和设计一致。

证据文件：`render_1000x1000.png`、`render_700x1100.png`、`render_1400x500.png`、`render_800x600.png`（就在本目录内）。

### 第 3 层：RED 检验（证明这套检查不是空转）
一个「全部通过」的检查，也可能是永远都会通过的假检查。所以我故意做了 3 个坏的变异体，看检查能不能抓到：

| 变异 | 实测 | 检查结果 |
|---|---|---|
| 真椭圆 `rx=80 ry=50` | 384×240 | **FAIL，已捕获** ✅ |
| 圆心偏移 `cx=160` | 288×384（被右边界裁切） | **FAIL，已捕获** ✅ |
| `figure` 改 `aspect-ratio: 3/2` | 256×256 | PASS（未捕获）⚠️ |

第 3 个变异没被抓到，但原因不是检查失灵，而是**实现本身把它挡住了**：SVG 的 `preserveAspectRatio` 保证容器变形时圆只缩放不变形。也就是说这个「漏检」恰好反向证明了前面那个设计选择是有效的。检查确实有鉴别力（前两个真实偏差都被抓到）。
