- **最高影响问题**：
  1. 图表「数值与数据一致」如何被第三方复算——若数值只以像素高度表达，无法核验；需把原始值落到 DOM（`data-value` 属性 + 可见标签）。
  2. 筛选后月份轴该固定还是随筛选收缩——影响空月份表现与空态判定。
  3. 「非法输入」在只有 `<select>` 的表单里用户无法产生，需提供可被外部注入的入口，否则该条验收无法实操。
  4. 内联 SVG 的柱体动画依赖 SVG2 几何属性过渡，跨浏览器兼容性未知（仅影响观感，不影响数值正确性）。

- **推荐方案（均衡偏大胆）**：
  数据模型＝「一行一订单」（`{id, month, region, amount}`，30 行，5 个地区 × 6 个月，含 1 个超长地区名）；KPI 三项全部由 `computeStats(rows)` 纯函数实时算出；筛选用 `<select>`（全部 + 各地区）；柱状图用**内联 SVG**，含 Y 轴刻度、网格线、每根柱顶数值标签，柱体带 `data-month/data-value`；月份轴取**全量数据的月份并集**（筛选后保持稳定，空月份画 0 高柱并标注）；空结果在图表区渲染空态文案并给 KPI 置 0/—；对外暴露 `window.__app`（`setFilter/setData/render`）以便对非法输入与空数据做真实注入测试；页面内置 `window.__uncaught` 错误收集器用于「不抛未捕获异常」的机器核验。
  多做什么：轴与网格、数值标签、hover tooltip、选中态高亮、数值确定性格式化（手写千分位，不依赖 `toLocaleString`，保证 node 侧可复算）。
  冒什么险：SVG 比 div 条更复杂，标签在窄视口可能挤压（用 `overflow: visible` + `text-anchor: middle` 缓解）。
  为什么值：要求 3 要「数值与数据一致」，把数值**写进 DOM** 比写进 CSS 高度可核验得多；这是本任务唯一的高价值复杂度。

- **其他选项（已否掉，信息性）**：
  - 保守：原生 `<table>` + div 高度条，无轴无数值标签 → 否，数值不可核验，且「视觉层级清晰」难达标。
  - 大胆：Canvas 画图 + 自绘动画 → 否，Canvas 内容不可被 DOM 读取，第三方无法复算，验收成本反而最高。
  - 用 ECharts/Chart.js CDN → 否，违反「无外部 CDN、离线可运行」。
