| 变异 | 杀死的断言数 |
|---|---|
| 英寸系数 0.0254→0.0255 | 1 |
| 英尺系数 0.3048→0.3049 | 1 |

15/15 变异体全部被杀。**这个过程真抓到了我自己的漏洞**：最初变异 4、11（都改华氏→摄氏公式）
杀死数为 0，原因是我的变异杀伤清单里**根本没有华氏→摄氏的用例**；补上 `212°F→100°C`、
`98.6°F→37°C`、`0°F→-17.7778°C` 后才杀掉。类似地，最初的精度断言把「整数位数」误当「小数位数」，
把 `123456000` 判成 9 位超长小数 —— 也是被这套验证自己逼出来的。两条都已修正并复跑。

## 5. 考虑过的方向与取舍（为何选这个）

| 方向 | 判决 | 理由 |
|---|---|---|
| CDN + Vue/React | 否 | 直接违反「无外部 CDN、离线可运行」 |
| 多文件 + 构建产物 | 否 | 违反「单文件」；且给运行增加前提 |
| `input type="number"` | 否 | 浏览器会静默吞掉字母等非法字符，用户拿不到「非法输入提示」，与验收项 3 冲突。改用 `type="text" + inputmode="decimal"` 自己校验 |
| 点「计算」按钮触发 | 否 | 验收项 1 明确要求无计算按钮 |
| **内联纯函数核心 + 标记块隔离 + 事件驱动 UI** | **选** | 既满足单文件离线，又让核心逻辑能被外部脚本**原样提取复算**，把「验证」做成可复算证据而非口头声明 |

实现细节上的取舍：

- **负长度/重量 → 硬拦截**；**负温度 / 低于绝对零度 → 不拦截，给 warn + 照常给算术结果**。
  理由：任务点名「负数长度」是非法输入要拦；而负温度是合法输入（`-40°C` 是标准用例），
  把「低于绝对零度」也变成死路会误伤 `-40` 这类正常用例，所以选择「诚实标注物理无意义 + 仍给结果」。
- **精度取 8 位有效数字**：够覆盖 `1 in = 2.54 cm`、`1 mi = 1.609344 km`、`1 oz = 28.349523 g` 这类
  有意义小数，又不产生长尾噪声。
- **交换按钮点击后把焦点移回「源单位」**：方便纯键盘连续操作。
- **未做全角数字归一化**：判断为超出「范围克制」（用户不会因为打不出半角数字而被卡住），
  但作为未处理项记录在 §6。

## 7. 给复核者的自验步骤

1. 直接双击 `app.html`（或拖入浏览器），打开 DevTools → Network，确认**零网络请求**。
2. 输入框输 `1`：长度 `米 → 厘米` 应显示 `100`；把输入框清空 → 显示 `—` 并提示「请输入数值」。
3. 输 `abc` → 显示 `—`，红框，提示「不是有效数字」；输 `-5` → 提示「长度不能为负值」。
4. 点「温度」→ 输 `0` → `32`；输 `-40` → `-40`；把「从」切到 `开尔文`、输 `0` → `-273.15`。
5. 全程只用键盘：`Tab` 依次经 类别→数值→源单位→交换→目标单位，下拉用 `↑↓`，
   按钮用 `Enter`/`空格`，确认能独立完成第 2–4 步。
6. 把窗口拉窄到手机宽度，检查布局与可点区域。
