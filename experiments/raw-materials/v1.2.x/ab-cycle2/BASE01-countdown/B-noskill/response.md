## 2. 实现要点
- **结构**：`分钟输入框` + `开始 / 暂停 / 重置` 三个按钮 + `MM:SS` 大号数字显示 + 状态提示行 + 归零横幅。
- **计时**：不用「每秒减 1」，而是记录 `endAt = Date.now() + remainingMs`，每 100ms 用时间戳重算剩余量 → 不会因定时器漂移累计误差；显示时向上取整到秒。
- **状态机**：`idle → running ⇄ paused → finished → (reset) idle`。`data-state` 属性驱动配色/按钮可用性/提示文案，状态变化有视觉反馈（蓝=运行、黄=暂停、红=闪烁告警）。
- **交互反馈**：
  - 输入时实时预览（合法 → 「将倒计时 01:00，点开始启动」；非法 → 红色错误文案，输入框加红框感）
  - 运行中输入框与「开始」自动锁定；暂停时「开始」变「继续」
  - 归零：红色边框 + 脉冲动画 + 「⏰ 时间到！」横幅 + 浏览器标签标题变化 + Web Audio 蜂鸣（`try/catch` 降级，音频不可用也不报错）
  - `Enter` 可直接开始
- **无持久化**：不写 localStorage/cookie，刷新即回到 `idle / 00:00`。

## 3. 边界与非法输入处理
所有校验集中在纯函数 `parseMinutes(raw)`（`app.html` 内的 `window.__countdown.parseMinutes`），单一入口、返回 `{ok, ms, error}`，绝不抛异常：

| 输入 | 行为 |
|---|---|
| `''` / `'   '` / `null` | 输入中给引导语「等待输入…」；点「开始」报「不能为空」 |
| `'0'` / `'0.0'` | 「分钟数必须大于 0」 |
| `'-3'` / `'abc'` / `'5abc'` / `'1e5'` / `'0x10'` / `'NaN'` / `'Infinity'` | 「格式不正确」（用 `^\d+(\.\d+)?$` 白名单正则，避免 `Number()` 的隐式转换陷阱） |
| `'0.0001'` | 「太短了，至少 1 秒」 |
| `'1441'` / `'999999'` | 「太长了，最多支持 1440 分钟（24 小时）」 |
| 长度 > 10 的字符串（含 200 字符超长文本） | 「输入过长」（另有 `maxlength=10` 在 UI 层兜底） |
| 合法：`'1'` / `'0.5'` / `' 2.5 '` / `'1440'` | 正常解析为毫秒 |

结构性兜底：`init()` 先逐个检查 `getElementById` 是否取到元素，缺失则静默 return；音频、`input.focus()` 均包在 `try/catch` 内。

## 5. 不确定 / 已知取舍
1. **蜂鸣声**：用 Web Audio 现场合成（无音频文件、无外部依赖）。在用户从未交互过就自动开始播放的场景、或系统静音/浏览器策略下可能无声——已 `try/catch` 静默降级，不影响视觉提示，但这意味着「声音提示」不是 100% 可保证，**视觉+标题+横幅提示是主保证**。
2. **上限 1440 分钟是我自行设定的**（task.md 只要求处理非法/超长输入）。若产品预期支持更长时长，需要调整 `MAX_MINUTES`。
3. **小数分钟**：允许 `0.5`（=30 秒），最小 1 秒。task.md 未明确，属自主决定的宽容策略。
4. **超长文本的 `maxlength=10`** 会阻止粘贴超过 10 字符的内容；即便绕过（如脚本直接赋值），`parseMinutes` 仍会拦截，两层都有。
5. **Chrome headless 用的是虚拟时间**（`--virtual-time-budget`）来压缩等待，因此「真实墙钟 60 秒」未被逐一等待；但走的是同一个 `setInterval` + `Date.now()` 路径，且 4.2 的假时钟单测覆盖了 1 分钟级的完整归零。
6. 未在 Firefox / Safari 实测，仅 Chromium（Chrome）+ node 双路验证。
