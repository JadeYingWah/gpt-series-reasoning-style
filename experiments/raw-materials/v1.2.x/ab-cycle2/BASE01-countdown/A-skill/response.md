## 3. 边界测试：测了哪些、怎么测、结果

| 边界 | 测法 | 输入 | 结果 |
| --- | --- | --- | --- |
| 空输入 | 设空值 + 派发 `input` 事件 + 真实点击开始 | `""` | 拦截，提示「请输入分钟数（不能为空）」，不启动、无异常 |
| 零值 | 同上 | `"0"` | 拦截，提示「分钟数必须大于 0」 |
| 字母 | 同上 | `"abc"` | 拦截，提示「只能输入数字…」 |
| 负数 | 同上 | `"-5"` | 拦截（负号不被正则接受） |
| 科学计数法 | 同上 | `"1e3"` | 拦截（同上，不误判为 1000） |
| 超上限 | 同上 | `"1441"` | 拦截，提示「不能超过 1440（即 24 小时）」 |
| **超长文本** | 注入 2000 字符后再点开始，并回读 `input.length` 确认确实写入 | `"9"×2000` | 长度闸门先于数值解析生效，拦截且不崩；`inputLen=2000` |
| 边界合法值 | 启动 `0.05` 分钟（=3s） | `"0.05"` | 正常运行并在约 3s 后归零，无异常 |
| 归零后行为 | 归零后再次点击开始 | — | 重新读取输入框重新开始，状态机不卡死 |
| 重复点击 | 运行中连点开始 | — | `start()` 首行 `if (state==='running') return`，不产生第二个定时器（`hasTicker` 恒为单例） |
| 暂停中暂停 | `paused` 态点暂停 | — | 直接 return，无副作用 |
| 刷新 | `Page.reload` 后读取状态 | — | 回到 `idle/00:00`，无持久化（符合要求 4） |

额外防护（非断言项，代码层）：`tick()` 整体包在 `try/catch` 中，渲染异常会降级为「暂停 + 提示」而不冒泡；
Web Audio 提示音整段 `try/catch` 包裹，音频不可用时静默降级，绝不因此抛未捕获异常。

## 4. 考虑过哪些方向、为何选这个

1. **计时内核：`setInterval` 每秒减 1 vs 时间戳驱动** → 选后者。前者在后台标签页节流/长任务阻塞下必然漂移；
   后者以 `endAt` 为唯一真值，每 100ms 重算，显示层按秒去重写入（减少 DOM 抖动），漂移不累积。
2. **零依赖 vs 引 CDN 框架** → 选零依赖。硬约束是「无外部 CDN、离线可运行」，引入框架直接违规；
   且该 UI 的复杂度（一个输入框 + 三个按钮 + 一个环）用原生实现更小更稳。
3. **归零提示形式：只变文字 vs 三通道冗余** → 选三通道：①状态胶囊由「运行中」变红色「时间到」；
   ②横幅 `role="alert"` 出现；③圆环与数字变红 + 呼吸式闪光动画；另附可降级的提示音。
   理由是「明显提示」在验收里是主观词，多通道冗余最能抗解释争议。
4. **进度反馈：纯数字 vs 数字 + 环形进度** → 选后者。环形让「还剩多少比例」一眼可见，
   是「交互状态要有明确反馈」的直接落点，成本仅一个 SVG 圆。
5. **是否加预设按钮（1/5/10 分钟）** → **不加**。任务要求是「可输入分钟数」，预设属于未被要求的功能扩张，
   按范围克制原则主动排除（如果确有需要，可在下一轮追加）。
6. **超长文本策略：设 `maxlength` 截断 vs 校验层拦截** → 选校验层拦截。
   加 `maxlength` 会让「超长输入」这条边界变得不可达，等于把要防的错误藏起来而不是处理它。
