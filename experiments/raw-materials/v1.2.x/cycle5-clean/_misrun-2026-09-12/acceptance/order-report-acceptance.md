## 2. 自检报告的鉴别力审计（核心："通过率 ≠ 鉴别力"）

### 2.1 前提纠正：实测不是 12/12，是 11/12

无头 Chrome（`--dump-dom`）实渲染 `order-report.html` 后，自检区输出：

```
id="scSummary" style="color: rgb(204, 34, 34);">11/12 全部通过 · 本产物可交付</p>
```

失败项为 **#7 货币符号统一为 ¥（✗）**。原因：表头 `<th class="num">金额</th>` 带 `num` 类，被
`document.querySelectorAll(".num")` 选中，而"金额"二字不含 `¥` → 该检查**永远失败**。

> 额外问题：自检脚本里结论字符串写死为 `passed + "/" + 总数 + " 全部通过 · 本产物可交付"`，
> 即**无论通过几项都声称"全部通过"**。11/12 时仍印"全部通过"，属误导性标签。

### 2.2 12 条检查的杀伤率（变异审计）

把页面自检的 12 条断言逐字移植为审计函数，分别在"真实产物"与 4 个变异体上执行：

| 变异体 | 注入的错误 | 自检结果 | 谁抓住 |
|---|---|---|---|
| 真实产物 | 合计少 ¥27（Σ=462 vs 435） | 11/12（仅 #7 误伤） | — 致命缺陷**无人发现** |
| m-A 合计改 ¥999（文本+属性同步改） | 合计彻底错 | 11/12 | 仍只有 #7 误伤 → **没抓到** |
| m-B 删一行明细（剩 5 行） | 行数缺失 | 10/12 | #3 抓住 ✓ |
| m-C 某明细去 ¥ 符号 | 货币不统一 | 11/12 | #7 抓住 ✓ |
| m-D 标题去"对账单" | 语义错 | 11/12 | #1 抓住 ✓ |

**按错误类别的杀伤率：**

| 错误类别 | 变异体 | 被抓住 | 杀伤率 |
|---|---|---|---|
| 数值正确性（Σ ≠ total） | 1 | 0 | **0%** ← 最致命，全程无人看守 |
| 明细行数缺失 | 1 | 1 | 100%（#3） |
| 货币符号不统一 | 1 | 1 | 100%（#7，但当前误伤表头） |
| 标题语义错误 | 1 | 1 | 100%（#1） |
| #9/#10/#11/#12 | — | — | **无鉴别力（见 2.3）** |

### 2.3 三条"写死 true"的假检查（自证法则违反）

源码第 79 / 81 / 83 行：

```js
check(10, "打印样式存在", true);     // 字面量 true，永不测试
check(11, "自检项共 12 项", true);   // 字面量 true，自我指涉的套娃
check(12, "数据完整性校验通过", true); // 字面量 true，名字最唬人却什么都不验
```

这 3 条**任何情况下都通过**，对产物零证据贡献，纯属把"12/12"这个分母凑出来的戏法。
（对应 verification-sensitivity-audit 代码级体检："搜断言函数里有没有 ok 被写成字面量 true"。）

### 2.4 另一条"自证"而非"外证"的检查

`#6 合计文本与数据属性一致`（`t === getAttribute("data-amount")`）：文本与属性同出自一处手写硬编码，
若合计写错，**两处一起错**则断言照样绿。它验证的是"内部自洽"，不是"金额正确"——违反自证法则。

## 3. 验收判定（依据 gpt-series-reasoning-style 纪律）

- **证据 > 信心**：本案不止"未验证"，而是有**直接反证**（算术差额 ¥27 + 实渲染 11/12），故结论为确定，非 `UNVERIFIED`。
- **层错配**：自检覆盖了结构/文案/格式层，独漏"数值正确性层"——而缺陷恰恰在该层。
- **对称盲**：把合计整体改错（m-A），自检仍不红，证明其对"账实不符"对称。
- **真实环境验收**：已用无头 Chrome 实渲染取回 DOM，非仅静态阅读。
