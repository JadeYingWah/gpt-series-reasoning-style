## 1. 分工判断总表

| 项目部分 | 判断 | 归属 | 理由 |
|---|---|---|---|
| 总体架构、任务包 schema、接口定义 | **自己干**（形态一） | 指挥官（我） | 必须"一个脑子"想完，拆给两边会造成集成地狱；且是后续所有并行的前提 |
| 核心编排器、示例执行器的实现 | **派子 agent 并行**（形态二） | 代码A / 代码B | 接口冻结后完全独立；实现+调试的中间过程量大，会污染主上下文 |
| 测试套件 | **派子 agent 并行**（形态二） | 测试 | 对着接口规格写即可，可与实现并行；**不看实现**形成双盲，测试质量更高 |
| 文档初稿（README / 设计文档） | **派子 agent 并行**（形态二） | 文档 | 冻结接口后独立成稿；每条命令真跑附输出，属机械但耗上下文的活 |
| 集成、端到端红绿验证 | **自己干**（形态一） | 指挥官（我） | 委派不转移最终责任；执行者说完成≠验收，闭环必须由 DRI 亲自核验 |
| 独立代码审查 | **派子 agent**（形态二） | 审查者 | 需要独立挑刺视角（新鲜上下文），且审查者按纪律不亲自改码 |
| 外部模型对抗评审 | **协调外部模型**（形态三，可选） | 外部模型 → 经总指挥转述 | 仅当需要**跨模型第二意见**（与内审形成去相关双盲）或总指挥指名时启用；转述往返成本高，从严使用 |
| 最终交付汇报 | **自己干**（形态一） | 指挥官（我） | 唯一 DRI 收口，执行者不得直接对用户 |

判断依据一句话：**要一个脑子的自己干；冻结接口后独立、可并行、会污染主上下文的派子 agent；只有"换个模型才有增量"的活才走外部转述。**

## 2. 子任务清单（每包按七要素）

### T0 设计与接口冻结｜形态一·我
- **目标**：定架构（模块清单+职责边界）、任务包 schema（字段级）、目录结构、数据流；产出 `DESIGN.md` + `task_pack.schema` + schema 自检脚本。
- **完成标准**：三件产物齐全；自检脚本对「合法包通过 / 缺字段 / 类型错 / 引用不存在执行器」四类各有输出证据；**总指挥确认冻结**。
- **交回给谁**：总指挥（冻结门禁）。

### T1 核心编排器实现｜形态二·子 agent 代码A
- **背景**：接口已冻结（以 T0 冻结版为唯一依据）。
- **目标**：实现解析校验 / 分发执行 / 状态台账 / 汇总报告四模块。
- **完成标准**：①合法 demo 任务包一条命令端到端跑通，产出台账+报告（贴实际输出）；②三类非法包被拒且错误信息可读（"可读"由指挥官判定，不由执行者自评）；③交付附三句证据：做了什么 / 怎么验的 / 没验什么。
- **允许与禁止**：只做规格内实现与必要调试；禁改 schema、禁加规格外功能、禁碰 T3/T4 产物。
- **交回给谁**：指挥官（我），不直接对用户。

### T2 示例执行器与 demo｜形态二·子 agent 代码B
- **目标**：3 个示例执行器（echo / 文本变换 / 简单计算）+ 1 个 demo 任务包。
- **完成标准**：demo 场景一条命令复现，输出与 **demo 任务包内声明的预期**一致（自查修订 2026-09-16：原"与文档描述一致"与并行中的 T4 循环依赖，文档一致性核对移至 T5/T7）；执行器只依赖冻结接口，不引用核心私有符号（指挥官以 import 检查核验）。
- **允许与禁止**：禁改核心代码与 schema。
- **交回给谁**：指挥官。

### T3 测试套件｜形态二·子 agent 测试
- **目标**：对着 T0 接口规格写单测：schema 校验、分发成功/失败路径、台账一致性、报告生成。
- **完成标准**：①覆盖正常/边界/异常三段输入域；②全绿；③**变异验证**——向核心注入 1 个故意 bug，至少 1 个用例变红，留红绿两态记录（防"全绿不算证据"）。
- **双盲约束**：只看规格不看 T1 实现；实现细节引入的 bug 由 T6 审查兜底。
- **交回给谁**：指挥官。

### T4 文档初稿｜形态二·子 agent 文档
- **目标**：README（是什么/安装/快速上手）+ 设计文档用户面（架构总览、任务包格式、如何新增执行器）。
- **完成标准**（自查修订 2026-09-16：原"每条命令真实执行过"在并行期不可达成——T1/T2 代码尚未合并）：文档与冻结 schema 逐字段一致（零出入）；所有命令写全并**逐条标注验证状态**（已跑过/待集成验证），未跑过的命令**不得附"实际输出"**；命令级真跑验证由 T5（集成后）与 T7（终审）执行。
- **允许与禁止**：禁臆写命令输出、禁写实现里不存在的功能。
- **交回给谁**：指挥官。

### T5 集成与端到端验收｜形态一·我
- **目标**：合并 T1–T4，端到端真跑一遍。
- **完成标准**：①端到端命令+输出留档；②红绿验证——故意做一次本该被防住的错误（注入坏包/坏执行器），断言变红留档；③复核 T3 的变异记录。
- **交回给谁**：总指挥（阶段汇报），产物送 T6。

### T6 独立审查｜形态二·子 agent 审查者
- **目标**：怀疑视角挑刺：验证证据是真的吗？边界漏了吗？文档与实现有出入吗？
- **完成标准**：问题清单（位置 + 为什么是问题 + 建议 + 严重级）+「通过 / 驳回 / 有条件通过」结论。
- **允许与禁止**：不亲自改交付物；不提超出完成标准的吹毛求疵。
- **交回给谁**：指挥官裁决（改/收），不直接指挥执行者。

### T7 终审与交付｜形态一·我
- **目标**：裁决 T6 意见（要改的派回原执行者）、文档终审、清理临时文件、交付汇报。
- **完成标准**：交付汇报三件套（做了什么 / 怎么验的〔给可复现命令〕/ 哪些没验〔明标 UNVERIFIED〕）；交付目录无临时物；文档与实现终版一致。
- **交回给谁**：总指挥（最终验收）。

### T8 外部模型对抗评审｜形态三·可选（经总指挥转述）
- **触发条件**：总指挥指名要多 Agent/外部模型，或需要与 T6 形成跨模型双盲的第二意见。
- **目标**：外部模型对集成产物独立挑刺。
- **完成标准**：问题清单交回我裁决；不直接改码。
- **通道**：无跨模型直连 → 七要素任务包（自包含）由**总指挥转述**到目标模型会话；总指挥说「已转述」才算派发；交回物同样由我对照原始目标先查跑偏、再裁决。
- **从严理由**：转述往返成本高，只有"换模型才有增量"的活才走这条；默认不启用。
- **若启用，最佳外派候选排序**：①T2 示例执行器（自包含、接口可冻结、验收标准客观，交接成本最低）；②终稿对抗评审（跨模型盲区与 T6 内审去相关）。T1 核心与 T5 集成**不外派**（连续性/责任核心）。

## 3. 执行顺序与门禁

```
T0 设计冻结（我）
   ↓ ⏸ 门禁：总指挥确认范围 + 接口冻结
T1 ∥ T2 ∥ T3 ∥ T4   ←—— 形态二·四路并行
   ↓（四包交回，我逐一亲自验收，不听信自报完成）
T5 集成与红绿验证（我）
   ↓
T6 独立审查（子 agent）
   ↓
T7 终审与交付（我）——（可选）T8 外部评审并行插入此阶段
```

并行说明：T1/T2/T3/T4 互不依赖，只依赖 T0 冻结版接口；T3 与 T1 保持双盲。任一路失败两次同法即停，换路或回报，不死磕。

**文件所有权边界（并行期防互踩）**：T1 只写 `src/orchestrator/`；T2 只写 `examples/`；T3 只写 `tests/`；T4 只写 `docs/`；schema 与目录结构归 T0/指挥官所有，任何人不得越界改动。所有权表随 T0 冻结版一并发布，越界改动验收时一律打回。

## 4. 红线（全程适用）

1. 执行者自报「完成」不算验收，指挥官逐一亲自核验后才收。
2. 审查者不亲自改；执行者不直接对用户。
3. 任务包七要素（背景/已定决策/未定缺口/完成标准/允许与禁止/唯一 DRI/交回给谁）不齐不派发。
4. 没验过的结论一律明标 UNVERIFIED，不装全验。
5. 本方案获总指挥批准后，先在项目根建 `_agents/`（填好指挥官/执行者/审查者三份模板），再开始派发。
