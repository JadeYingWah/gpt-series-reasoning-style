## 2. 形态叠加判断（核心结论：三种形态叠加，不是三选一）

| 工作部分 | 形态 | 判断依据 |
|---|---|---|
| 架构与接口设计（目录结构、模块接口签名、数据格式） | **形态一·自己干** | 这是所有并行工作的"脊柱"。它没冻结就把活派出去，子智能体和外部模型各写各的，集成时全部返工。串行依赖最强的部分不并行 |
| 核心模块（任务模型 + 存储 + CRUD） | **形态一·自己干** | 集成枢纽，与架构设计连续性最强，是所有其他子任务的依赖方 |
| 导入导出模块（JSON↔CSV） | **形态三·外部模型（经总指挥转述）** | 自包含、接口可冻结、验收标准客观（测试全绿）。这是交接成本最低、最适合跨模型的部分。任务"大到要分工"命中形态三开启条件 |
| 文档（README + CHANGELOG） | **形态二·子智能体并行** | 完全独立的子活，接口冻结后即可动笔，干完交结果即可，不与代码争抢上下文 |
| 测试用例矩阵（边界/异常） | **形态二·子智能体并行** | 基于冻结接口可**先行编写**（用例与实现分离，天然形成交叉验证：用例与实现不一致恰好暴露理解偏差）；同时产出大量中间用例，隔离在子智能体上下文里防污染主线 |
| 集成与联调 | **形态一·自己干** | 主智能体是 DRI，组装各路交付、跑全量测试，不可委派 |
| 独立代码审查 | **形态二·子智能体（审查者角色）** | 需要"独立挑刺视角"——命中形态二开启条件 |
| 最终验收与向总指挥汇报 | **形态一·指挥官本人** | 委派不转移最终责任；子智能体/执行者自报"完成"不算验收 |

**不派出去的部分（明确说清为什么）**：架构设计、核心模块、集成验收。凡是"拆出去会造成理解断层或集成风险"的都不派；凡是"干完交结果、边界清晰"的都派。

## 3. 子任务总表

依赖关系：T0 冻结接口后，T1/T2/T3/T4 四路并行 → T5 集成 → T6 审查 → T7 验收汇报。

| ID | 子任务 | 形态 | 承担者（DRI） | 目标 | 完成标准（可核验） | 交回给谁 |
|----|--------|------|--------------|------|-------------------|---------|
| T0 | 架构与接口设计 | 一 | 指挥官本人 | 产出 `ARCHITECTURE.md`：目录结构、三模块接口签名、JSON 数据 schema、测试验收口径 | 文件存在且含上述四项；接口签名具体到函数名/参数/返回值；**经总指挥确认后冻结** | 总指挥 |
| T1 | 核心模块实现 | 一 | 指挥官本人 | 按 T0 冻结接口实现任务模型/存储/CRUD | 本模块单元测试全绿；自述三句证据（改了啥/怎么验/没验啥） | 指挥官（自查） |
| T2 | 导入导出模块 | 三 | 外部模型（待总指挥指定） | 按 T0 冻结接口实现 JSON↔CSV 导入导出 | 详见 `_agents/taskpacks/T2-任务包-导入导出模块.md`（七要素） | 指挥官（经总指挥转述交回） |
| T3 | 文档写作 | 二 | 子智能体 A | 按 T0 冻结接口写 README + CHANGELOG | README 含安装/快速上手/命令参考三节且命令与实现一致；CHANGELOG 含本版本条目；**在真实终端按 README 走一遍快速上手，每条命令可复现** | 指挥官 |
| T4 | 测试用例矩阵 | 二 | 子智能体 B | 基于冻结接口写边界/异常用例（空文件/损坏 JSON/CSV 注入/超长字段/并发写等），用例先于集成 | 用例覆盖输入域三段（正常/边界/异常）；每条用例带预期结果；独立成文件不与 T1/T2 实现耦合 | 指挥官 |
| T5 | 集成与联调 | 一 | 指挥官本人 | 组装 T1+T2，跑 T4 全量用例 | 全量测试通过；**故意注入 1 个错误断言确认会红**（证明用例有鉴别力，全绿不算证据）；关键功能在真实终端跑一遍 | 指挥官（自查） |
| T6 | 独立审查 | 二 | 审查者子智能体 C | 对照各任务包完成标准抽查交付 | 产出问题清单（位置+为什么是问题+建议改法）或明确"通过/驳回/有条件通过"；不亲自改交付物 | 指挥官 |
| T7 | 最终验收与汇报 | 一 | 指挥官本人 | 处理 T6 意见，独立核验，向总指挥汇报 | 汇报含三件：做了什么 / 怎么验的（给可复现命令）/ 哪些没验 | 总指挥 |

## 4. 时序与依赖

```
T0 架构冻结（串行，先做）
   ├── T1 核心模块（形态一，自己干）
   ├── T2 导入导出（形态三，外部模型 ← 经总指挥转述）
   ├── T3 文档（形态二，子智能体 A）      ← 四路并行
   └── T4 测试矩阵（形态二，子智能体 B）
T5 集成联调（T1+T2+T4 汇合）
T6 独立审查（形态二，审查者 C）
T7 最终验收 → 向总指挥汇报
```

---

## 5. 协作红线（全流程适用）

1. 执行者/子智能体说"我做完了"**不算验收**——只说"按标准做完了，请验收"。
2. 审查者不亲自改交付物，只出问题清单交指挥官。
3. 不绕开指挥官直接向总指挥汇报。
4. T2 的任务包经总指挥转述给外部模型，总指挥说**"已转述"才算派发**；交回同样经转述。
5. 各承担者只改任务包允许范围内的文件；临时文件不进交付目录，收尾清掉。
6. 同一动作连续失败 2 次，禁止同法第 3 次，先判断是否换路。
7. 交付只说三件：做了什么 / 怎么验的 / 哪些没验。

---

## 6. 派发流程（待总指挥批准后执行）

1. **总指挥批准本方案**（或提出修改）。
2. 指挥官派发形态二子智能体（T3 文档、T4 测试矩阵；T6 审查在 T5 后派）。
3. 总指挥**指定外部模型**并转述 `_agents/taskpacks/T2-任务包-导入导出模块.md`，回复"已转述"即视为 T2 派发生效。
4. 各路交回后，指挥官对照原始目标逐项验收 → 审查者挑刺 → 意见回指挥官裁决 → 最终汇报。
