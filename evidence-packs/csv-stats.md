# CSV 统计/汇总+HTML 报告：历史致命缺陷模式清单（证据包 v1）

> 来源：P2 双臂实验 T6 四臂 fatal（机械判定台抓取，2026-09-15）。每条四件套：模式 / 双向致命 / 自查输入 / 检测思路。
> 可选参考，不构成验收标准。**双向致命原则见 README**。

## 编码族（本类任务历史最大坑，4 个臂全部中招）

### 1. GBK/ANSI 输入文件
- **来源**：P2 round1/round2 四臂全中（F3×3）
- **双向致命**：GBK 文件按 UTF-8 读 → 乱码或崩溃（漏报）；把合法 UTF-8 中文误判为 GBK → 内容损坏（误伤）
- **自查输入**：同一份中文 CSV 分别存成 UTF-8 与 GBK 各喂一次
- **检测思路**：先探测编码（BOM/字节特征），两者都正确解析；不确定时显式报错而非猜

### 2. UTF-8 BOM
- **来源**：T6 判定台 probe_bom，多臂栽过
- **双向致命**：BOM 混进首列表头 → 表头校验失败或首行数据损坏；无脑剥 BOM → 上游本来就没有 BOM 时无影响（安全方向）
- **自查输入**：带 EF BB BF 前缀的 CSV
- **检测思路**：读入后剥 `\ufeff`，表头匹配在剥离后进行

### 3. CRLF 行尾
- **来源**：T6 判定台 probe_crlf
- **双向致命**：`\r` 混进最后一个字段 → 统计错；按通用行分割则无风险
- **自查输入**：CRLF 换行的 CSV
- **检测思路**：以 `csv` 模块或 strip `\r\n` 处理，断言末字段不含 `\r`

## 数值语义族

### 4. 空/非法金额字段
- **双向致命**：静默按 0 参与统计 → 错数（历史最常见）；把"空"当错误拒绝整文件 → 可用性破坏。**关键是声明口径**：空值计入 count 不计入 sum/avg（或相反），并在输出中声明
- **自查输入**：一行金额为空、一行金额为 `abc`
- **检测思路**：空值与非法值分开处理；口径写进输出说明

### 5. 引号内逗号/换行（CSV 解析）
- **双向致命**：裸 split(",") → 字段错位统计全错；用 csv 模块则天然正确
- **自查输入**：`"Smith, John",760.5` 型记录
- **检测思路**：禁止手写 split，用标准 csv reader

## 输出族

### 6. HTML 注入（F2）
- **来源**：T6 判定台 probe 注入用例
- **双向致命**：name/note 含 `<script>` 未转义 → F2；把所有字符无脑转义 → 中文/正常文本显示损坏
- **自查输入**：name=`<script>alert(1)</script>`、note 含中文与 `&<>`
- **检测思路**：html.escape 所有动态字段，静态模板不转义；输出断言含原中文且不含裸 `<script>`

### 7. JSON schema 漂移
- **双向致命**：键名/结构自造 → 消费端崩；过度严格 → 合法变体被拒
- **自查输入**：与契约逐键对比
- **检测思路**：输出前逐键断言

### 8. 退出码纪律
- **双向致命**：错误路径返回 0 → 消费端以为成功（F3 级）；一切输入都报错 → 误伤
- **自查输入**：无参数 / 文件不存在 / 表头缺列 / 空文件 各一次
- **检测思路**：显式错误路径退出码非 0 且 stderr 有信息；正常路径 0
