# gpt-series-reasoning-style

一套交付验收纪律类 Skill——不教你写代码，教你别撒谎。

---

## 这是什么

这是一个给 AI 用的纪律层。它不提升代码质量，它提升的是**交付可信度**。

它的核心问题是：**"我觉得做完了"和"真的做完了"之间，有一条裂缝。**

这个 skill 就是那条裂缝上的检查线。

---

## 核心设计

### 三道工序

```
规划面（任务开始前）
    ↓
执行面（彻底忘记 skill，专心干活）
    ↓
审查面1（直觉检查——继续忘记 skill，用常识判断）
    ↓
审查面2（纪律检查——重新想起 skill，严格过一遍规则）
```

**执行面彻底忘记 skill**——这个设计很重要。
创作是创作，检查是检查，互不干扰。
做完了再回来检查，不打断心流。

### 审查面 7 条规则

1. **真打开看一眼**——别只看代码，真在浏览器/终端里跑一遍
2. **未验证标注**——没验过的就写"未验证"，别装成全验过
3. **失败两次换路**——同一方法失败两次，就换个思路，别死磕
4. **全绿不算证据**——测试全过不代表没问题，故意做一次错误才算验过
5. **关键数字重算**——数据类交付的关键数字，用独立方法重算一遍
6. **临时物隔离**——临时文件别进交付目录，收尾清掉
7. **防死循环**——同一个动作做三次没进展，就换思路

## 实验证据

### Test-Bed 1：轻任务（6个）
- 轻任务上价值小，但没副作用
- 成本可控，40行读一遍就完

### Test-Bed 2：中等任务（5个）
- 5个执行者一致评分 7.5-8分
- 一致结论：skill 不提升代码质量，提升交付可信度
- 最有用的规则：真打开看一眼、全绿不算证据

### Test-Bed 3：创意任务（1个）
- A臂真打开浏览器，抓到5处视觉问题
- B臂只做结构校验，没真渲染
- 结论：真打开看一眼这条规则是真的有用

### Test-Bed 4：复杂创意任务（1个）
- 两个臂都做了深度验证（桩测试、审计、截图）
- 即使 B 臂知道旧版 skill 的内容，也会自觉用那套纪律
- 结论：这套纪律学会了就忘不掉

## 核心结论

> **这个 skill 的价值不是"强制你做什么"，而是"让你知道该做什么，然后你自己就会做"。**

一旦知道了：
- 要真打开看一眼
- 要列未验证项
- 要做独立验证

你就再也回不去"我觉得行就交"了。

这就是它最有用的地方——**不是纪律，是习惯。**

---

## 适用场景

**推荐用：**
- 代码交付
- 数据报告
- 视觉产物
- 多 Agent 协作
- 任何"声称完成就要对产物负责"的场景

**不用：**
- 一句话问答
- 探索性草稿
- 纯聊天
- 无人验收的内部实验
